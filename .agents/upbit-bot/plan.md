# Plan 서브에이전트 지침 — 업비트 자동매매 (upbit-bot)

## 역할
업비트 시세를 이용한 가상화폐 자동매매 웹앱의 구현 계획(spec)을 작성한다. **코드는 작성하지 않는다.**

## 수정 가능한 범위
- `apps/upbit-bot/spec.md` **한 파일만** 새로 만든다.
- 그 외 파일은 읽기만 한다. 블로그 파일(`index.html`, `css/`, `js/`, `posts/`)과 다른 앱은 절대 수정하지 않는다.

## 배경
- 루트 `CLAUDE.md`를 먼저 읽는다. 순수 HTML/CSS/JS, 앱은 `apps/upbit-bot/` 안에서 자체 완결, CDN만 허용, 모바일 대응 필수.
- 참고용 기존 spec: `apps/london-trip/spec.md` (형식·구체성 수준 참고). 블로그 톤은 `css/style.css`.
- GitHub Pages 배포 → 모든 경로 상대 경로. 블로그 메인에 iframe 카드로 삽입된다.

## 사용자 결정 사항 (확정)
1. **모의투자 + 실거래 옵션**
   - 기본(블로그에서 동작): 업비트 **공개 시세 API/웹소켓**(`https://api.upbit.com/v1/...`, `wss://api.upbit.com/websocket/v1`)의 실시간 가격으로 **가상 잔고 모의투자**. API 키 불필요. 상태는 localStorage(try/catch).
   - 실거래 모드: 같은 폴더에 **로컬 Node.js 서버**(`server/` 하위, 예: `server.js` + `package.json` + `.env.example` + `README`)를 둔다. 사용자가 자기 PC에서 실행하면 브라우저 앱이 `http://localhost:{port}`로 붙어 실제 주문을 낸다. 서버가 업비트 JWT 서명(HS512 또는 업비트 현행 규격, `query_hash` SHA512)을 처리한다. **API 키는 PC의 `.env`에만**, 브라우저/저장소에 절대 두지 않는다. `.env`는 `.gitignore`.
   - 이유: 업비트 개인 API는 브라우저 CORS 미지원 + 키별 허용 IP 등록 필요 + 공개 페이지에 키 노출 위험.
   - 가능하면 Node 서버는 외부 의존성 없이(내장 `crypto`, `http`, `fetch`) 작성하는 방향을 검토.
2. **매매 기능: 자동매매 전략** (수동 주문 UI·손절익절 자동화는 사용자가 선택하지 않음 — 다만 안전장치로서 최소한의 것은 검토해 필요/선택으로 표기)

## spec.md에 반드시 담을 내용
1. 개요 (2~3문장)
2. 기능 목록 (필수/선택). 최소 검토 항목:
   - 마켓 선택(KRW 마켓 목록 조회), 실시간 현재가·등락률, 캔들 차트(가벼운 방식: canvas 직접 그리기 또는 CDN 경량 차트 — 추천과 이유)
   - 전략: 변동성 돌파(K값), 이동평균 골든/데드크로스(단기/장기), RSI 과매도/과매수 — 각 전략의 정확한 진입/청산 규칙, 사용할 캔들 단위, 파라미터와 기본값
   - 투자 금액/비중 설정, 봇 시작/정지, 매매 로그, 수익률·평가금액 표시
   - 업비트 수수료(0.05%)·최소 주문금액(5,000원)·호가 단위 반영
   - 모의/실거래 모드 전환 UI, 실거래 모드 진입 시 강한 경고와 확인 절차, 서버 연결 상태 표시, 1회 최대 주문금액 같은 안전 한도
   - 백테스트(최근 캔들로 전략 성과 미리보기) — 필요/선택 판단
   - 브라우저 탭이 닫히면 봇이 멈춘다는 점과 그 대응(서버 측 실행 여부) 정리
   - API 호출 제한(rate limit) 대응
3. 파일 구조 (`apps/upbit-bot/` 아래, 브라우저 앱 파일과 `server/` 분리) + 각 역할
4. 설계: 전략 로직은 DOM 없는 순수 함수(테스트 가능), 브로커 인터페이스(PaperBroker / LiveBroker) 추상화, 데이터 흐름
5. 로컬 서버 설계: 엔드포인트 목록(잔고, 주문, 주문 조회/취소 등), CORS 허용 범위(localhost 및 블로그 출처만), 요청 인증(로컬 토큰 등), 키 관리, 실행 방법
6. UI/레이아웃: 화면 구성 다이어그램, 375px 반응형, 다크 모드
7. 블로그 삽입 방안: 카드 제목·설명 초안, iframe 추천 여부
8. 검증 체크리스트: 전략 계산 예시 케이스(예: RSI 계산값, 변동성 돌파 목표가 = 시가 + (전일고가-전일저가)×K), 모의 체결·수수료 계산 예시, 서버 서명 검증 방법(실 키 없이 확인 가능한 범위)
9. 위험 고지 문구 초안 (투자 손실 책임은 사용자에게 있음, 수익 보장 없음)
10. 범위 밖

## 작성 규칙
- 한국어, 구현자가 이 문서만 보고 만들 수 있을 만큼 구체적으로.
- 업비트 API 엔드포인트·인증 규격은 최신 공식 문서(docs.upbit.com 등)를 확인할 수 있으면 확인하고, 확인 못 한 부분은 "확인 필요"로 표기한다.
- 끝나면 spec.md 핵심 요약(10줄 이내)과 사용자 결정이 필요한 사항 목록을 반환한다.
