# Plan 서브에이전트 지침 — 2048 게임

## 역할
2048 웹앱의 구현 계획(spec)을 작성한다. **코드는 작성하지 않는다.**

## 수정 가능한 범위
- `apps/2048/spec.md` **한 파일만** 새로 만든다.
- 그 외 파일은 읽기만 한다. 블로그 파일(`index.html`, `css/`, `js/`, `posts/` 등)은 절대 수정하지 않는다.

## 배경
- 프로젝트: 마크다운 블로그 + 미니 웹앱 포트폴리오. 순수 HTML/CSS/JavaScript. 규칙은 루트의 `CLAUDE.md`를 먼저 읽는다.
- 웹앱은 `apps/{앱이름}/` 폴더 안에서 자체 완결되어야 한다. 블로그의 CSS/JS를 import하지 않는다.
- 외부 라이브러리는 최소화(CDN 허용). 이 게임은 라이브러리 없이 만드는 것을 기본으로 한다.
- 블로그 디자인 참고용으로 `css/style.css`를 읽어 색상 톤(파란 헤더 `#2458d6`, 다크 모드 배경 `#16181c`, 시스템 한글 글꼴)을 파악한다. 게임도 이 톤과 어울려야 한다.
- 이 앱은 나중에 블로그 메인(`index.html`)에 카드(iframe 또는 미리보기)로 삽입된다. iframe 안에서도 잘 보이도록 고려한다.
- 사이트는 GitHub Pages에 배포되므로 모든 경로는 상대 경로여야 한다.

## 사용자 요구사항
- 2048 게임: 방향키로 숫자 타일을 밀어서 같은 숫자를 합치는 퍼즐 게임
- 점수판 포함

## spec.md에 반드시 담을 내용
1. **개요**: 무엇을 만드는지 2~3문장
2. **기능 목록**: 필수 / 선택으로 구분. 최소한 아래를 검토해 포함 여부를 정한다.
   - 4×4 보드, 시작 시 타일 2개, 이동마다 새 타일(2: 90%, 4: 10%)
   - 방향키 + WASD 입력, **모바일 스와이프** 입력(필수 — CLAUDE.md의 모바일 규칙)
   - 한 번의 이동에서 타일은 한 번만 합쳐지는 표준 규칙
   - 현재 점수, 최고 점수(`localStorage`, try/catch), 합칠 때 점수 증가 표시
   - 새 게임 버튼, 2048 달성 시 승리 안내(계속하기 가능), 더 이상 움직일 수 없으면 게임 오버 안내
   - 타일 이동/합치기/생성 애니메이션
   - 다크 모드(`prefers-color-scheme`)
   - 키보드 접근성, 스크린 리더용 점수 안내(aria-live)
3. **파일 구조**: `apps/2048/` 아래 파일 목록과 각 파일의 역할
4. **설계**: 게임 로직(보드 상태, 이동·합치기 알고리즘, 게임 오버 판정)과 렌더링을 분리하는 방법. 로직은 DOM 없이 테스트 가능한 순수 함수로.
5. **UI/레이아웃**: 화면 구성(제목, 점수판, 보드, 버튼, 안내), 반응형 기준(375px에서 보드가 화면에 맞게 줄어듦, 가로 스크롤 없음), 모바일에서 스와이프 시 페이지가 스크롤되지 않게 하는 방법
6. **블로그 삽입(Embed) 방안**: 카드에 넣을 제목·설명 문구 초안, iframe vs 미리보기 이미지 중 추천과 이유
7. **검증 체크리스트**: Review 단계에서 확인할 항목(이동/합치기 규칙 예시 케이스 포함, 예: `[2,2,2,2]` 왼쪽 → `[4,4,0,0]`, `[2,2,4,0]` 왼쪽 → `[4,4,0,0]`)
8. **범위 밖**: 이번에 하지 않을 것

## 작성 규칙
- 한국어로, 간결하게. 구현자가 이 문서만 보고 만들 수 있을 정도로 구체적으로.
- 작업이 끝나면 spec.md의 핵심 요약(10줄 이내)과 사용자 결정이 필요한 사항이 있으면 그 목록을 반환한다.
