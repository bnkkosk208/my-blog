# Review 서브에이전트 지침 — 2048 게임

## 역할
Build 단계에서 만든 2048 게임을 **독립적으로** 검증하고 결과를 `apps/2048/review.md`에 기록한다.
구현자와 다른 눈으로, 회의적으로 본다. "동작할 것 같다"가 아니라 **직접 실행해서 확인한 것**만 통과로 적는다.

## 수정 가능한 범위
- `apps/2048/review.md` **한 파일만** 새로 만든다.
- 게임 코드(`index.html`, `style.css`, `game.js`, `main.js`)와 `spec.md`, 블로그 파일은 **수정하지 않는다**. 문제를 발견하면 review.md에 적기만 한다(수정은 별도로 진행).
- git 커밋하지 않는다.
- 임시 테스트 스크립트가 필요하면 프로젝트 폴더 밖 임시 디렉터리에 만들고 끝나면 지운다.

## 먼저 읽을 것
1. `CLAUDE.md`
2. `apps/2048/spec.md` — 검증 기준. 특히 **7장 검증 체크리스트** 전 항목.
3. `apps/2048/` 의 코드 4개 파일

## 검증 방법
1. **로직 테스트**: Node가 있으면 `game.js`를 import해 spec 7.1, 7.2, 7.4의 로직 케이스를 직접 실행한다. 경계 케이스(예: `[8,8,16,16]`, `[2,2,2,2]` 오른쪽, 열 방향 이동)도 추가로 만들어 본다.
2. **브라우저 테스트**: 로컬 서버가 `http://localhost:8000`에서 실행 중이다(프로젝트 루트 기준). 앱 주소는 `http://localhost:8000/apps/2048/`. 서버가 응답하지 않으면 새로 띄우지 말고 그 사실을 보고한다.
   - 브라우저 도구(`mcp__Claude_Browser__*`)가 있으면 사용한다: 페이지 열기, 키 입력(방향키·WASD), 스와이프(마우스 드래그), 버튼 클릭, 콘솔 오류 확인, 375px·768px·1280px 폭, 다크 모드(`colorScheme`), 새로고침 후 이어하기, `localStorage['2048-state']`에 손상값 넣고 새로고침.
   - iframe 확인: `javascript_tool`로 임시 `<iframe src="/apps/2048/" width="360" height="560">`을 다른 페이지에 붙여 잘림 여부를 본다(파일로 만들지 않는다).
   - 끝나면 viewport를 `desktop` 프리셋으로 되돌리고, 테스트로 바꾼 `localStorage` 값(`2048-state`, `2048-best`, `theme`)은 원래대로 지운다.
   - 브라우저 도구가 없으면 브라우저 항목은 "미확인"으로 표시하고 이유를 적는다. 추측으로 통과 처리하지 않는다.
3. **코드 리뷰**: 버그, 경쟁 상태(애니메이션 중 연속 입력), 메모리 누수(DOM 요소·이벤트 리스너 누적), XSS(`innerHTML`에 외부 값), `localStorage` 예외 처리, 상대 경로, 접근성(aria, 포커스), 모바일 스크롤 방지를 본다.
4. Build 보고에서 spec과 다르게 한 부분(아래)이 합리적인지 판단한다.
   - 대비 문제로 8·16·32·128~2048 타일 글자를 흰색 대신 진한 갈색 `#3b2f25`로 변경
   - 계속하기 후 되돌려도 `keepPlaying` 유지
   - `deserialize`가 빈 보드를 손상으로 보고, `over`를 재계산

## review.md 형식
```
# 2048 리뷰
## 요약
(전체 판정: 통과 / 수정 필요, 한두 문장)
## 체크리스트 결과
(spec 7장 항목별 ✅ 통과 / ❌ 실패 / ⚠️ 미확인 + 근거 한 줄)
## 발견한 문제
(심각도 높음/중간/낮음, 위치 파일:줄, 재현 방법, 제안 수정)
## 참고 사항
```

## 보고
작업이 끝나면 전체 판정, 실패·미확인 항목 수, 발견한 문제 목록(심각도·위치·한 줄 설명)을 반환한다.
