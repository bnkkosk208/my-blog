지금까지 이 블로그는 내 컴퓨터에서 `python -m http.server`로 띄워야만 볼 수 있었습니다. 오늘은 **GitHub Pages**를 이용해 누구나 볼 수 있는 주소로 배포했습니다.

## GitHub Pages란?

GitHub 저장소에 있는 HTML, CSS, JavaScript 파일을 그대로 웹사이트로 보여 주는 무료 호스팅 서비스입니다. 이 블로그처럼 **빌드 단계가 없는 정적 사이트**라면 별다른 설정 없이 바로 올릴 수 있습니다.

배포하면 주소는 이런 모양이 됩니다.

```
https://<사용자이름>.github.io/<저장소이름>/
```

## 배포 순서

1. 프로젝트를 git 저장소로 만들고 커밋합니다.
2. GitHub에 **공개 저장소**를 만들고 푸시합니다.
3. 저장소 설정에서 Pages를 켜고, 배포할 브랜치를 `main`, 폴더를 루트(`/`)로 지정합니다.
4. 1분쯤 기다리면 사이트가 열립니다.

GitHub CLI(`gh`)를 쓰면 터미널에서 저장소 만들기와 푸시를 한 번에 할 수 있습니다.

```bash
gh repo create my-blog --public --source=. --remote=origin --push
```

> 무료 계정은 **공개 저장소**에서만 Pages를 쓸 수 있습니다. 저장소가 공개되면 코드뿐 아니라 **커밋 기록 전체**도 누구나 볼 수 있다는 점을 기억해야 합니다.

## 주의할 점 1: `.nojekyll` 파일

GitHub Pages는 기본적으로 **Jekyll**이라는 도구로 사이트를 한 번 가공합니다. 이때 맨 위에 `---`로 감싼 정보(front matter)가 있는 마크다운 파일은 HTML로 바뀌어 버립니다.

이 블로그는 브라우저가 `.md` 원본을 직접 `fetch`해서 화면에 그리기 때문에, 원본이 사라지면 글을 불러오지 못합니다. 그래서 저장소 루트에 **빈 `.nojekyll` 파일**을 두어 Jekyll 처리를 껐습니다.

```bash
touch .nojekyll
```

## 주의할 점 2: 상대 경로

사이트가 도메인 루트가 아니라 `/my-blog/` 아래에 올라가기 때문에, 경로를 `/posts/...`처럼 **슬래시로 시작하면** 엉뚱한 주소를 찾게 됩니다. 이 블로그는 처음부터 `posts/index.json`처럼 **상대 경로**로 작성해 두어서 수정 없이 그대로 동작했습니다.

## 주의할 점 3: 공개하면 안 되는 내용 걸러내기

배포 직전에 보니, 내부 문서를 옮겨 온 글 하나가 커밋 기록에 남아 있었습니다. 파일만 지우고 푸시하면 **이전 커밋에는 그대로 남아** 누구나 볼 수 있습니다. 그래서 푸시하기 **전에** 커밋 기록에서 완전히 빼고 올렸습니다.

- 한 번 푸시한 기록은 되돌리기 어렵습니다.
- 공개 배포 전에는 **글 내용과 커밋 기록을 함께** 점검하는 습관을 들이기로 했습니다.

## 이후 글 올리기

배포 설정은 한 번이면 끝입니다. 이제는 새 글을 쓰고 아래처럼 푸시만 하면 1분쯤 뒤 사이트에 반영됩니다.

```bash
git add posts/새-글.md posts/index.json
git commit -m "새 글 추가"
git push
```

바로 이 글도 그렇게 올렸습니다.
