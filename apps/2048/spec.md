# 2048 — 구현 계획 (spec)

## 1. 개요
4×4 보드에서 방향키·WASD·스와이프로 숫자 타일을 밀어 같은 숫자를 합치고 2048 타일을 만드는 퍼즐 게임이다.
현재 점수와 최고 점수를 보여 주는 점수판이 있으며, 라이브러리 없이 순수 HTML/CSS/JavaScript로 `apps/2048/` 안에서 자체 완결된다.
블로그와 같은 파란 톤·다크 모드를 따르고, 블로그 메인 카드의 iframe 안에서도 문제없이 동작한다.

## 2. 기능 목록

### 필수
| # | 기능 | 세부 |
|---|------|------|
| F1 | 보드 | 4×4. 시작 시 빈 칸 중 무작위 2곳에 타일 생성 |
| F2 | 새 타일 | **보드가 실제로 바뀐 이동**마다 빈 칸 1곳에 생성. 값 2(90%) / 4(10%). 변화 없는 이동은 타일 생성·점수 변화 없음 |
| F3 | 입력 | 방향키, WASD(대소문자 모두), 모바일 스와이프(Pointer Events). 애니메이션 중 입력은 무시하지 않고 즉시 다음 이동 처리(이전 애니메이션은 최종 상태로 스냅) |
| F4 | 합치기 규칙 | 표준 규칙: 이동 방향 쪽 타일부터 처리, 한 번의 이동에서 각 타일은 최대 1회만 합쳐짐 |
| F5 | 점수 | 합쳐져 생긴 타일 값의 합만큼 증가. 합칠 때 점수 옆에 `+N` 떠오르는 표시 |
| F6 | 최고 점수 | `localStorage` 키 `2048-best`. 읽기/쓰기 모두 try/catch, 실패 시 메모리 값만 사용 |
| F7 | 새 게임 | "새 게임" 버튼. 점수 0, 보드 초기화. 최고 점수 유지 |
| F8 | 승리 | 2048 타일 첫 생성 시 오버레이 "2048 달성!" + [계속하기] [새 게임]. 계속하기 후에는 다시 뜨지 않음 |
| F9 | 게임 오버 | 빈 칸 없음 + 인접(상하좌우) 동일 값 없음 → 오버레이 "게임 오버" + 최종 점수 + [다시 하기] |
| F10 | 애니메이션 | 이동(transform 슬라이드 ~100ms), 합치기(pop 확대 ~150ms), 생성(scale 0→1 ~150ms). `prefers-reduced-motion: reduce`면 끔 |
| F11 | 다크 모드 | `prefers-color-scheme` 대응. 추가로 블로그가 저장한 `localStorage['theme']`(`light`/`dark`)가 있으면 읽기만 해서 `data-theme`로 반영(같은 오리진이라 블로그 토글과 일치) |
| F12 | 접근성 | 모든 버튼 키보드 조작·포커스 링 표시, 보드는 `role="application"`+`aria-label`+`tabindex="0"`, 점수 변화·승리·게임오버를 `aria-live="polite"` 영역으로 안내(예: "점수 1024, 이동 +16"), 오버레이 열리면 첫 버튼에 포커스 |
| F13 | 되돌리기(1회) | "되돌리기" 버튼. 직전 이동 **한 번만** 취소(보드·점수·won/over 모두 이전 상태로). 되돌린 뒤에는 다음 이동 전까지 버튼 비활성. 새 게임 시작 직후·게임 로드 직후에도 비활성. 최고 점수는 되돌리지 않음. 게임 오버 상태에서도 되돌리기 가능(오버레이에 [되돌리기] 버튼 추가) |
| F14 | 이어하기 | 매 이동·새 게임·되돌리기 후 진행 상태를 `localStorage` 키 `2048-state`에 저장(try/catch). 페이지를 다시 열면 저장된 보드·점수·won/keepPlaying/over를 복원. 저장값이 손상·형식 불일치면 무시하고 새 게임. 되돌리기용 직전 상태는 저장하지 않음(복원 직후 되돌리기 비활성) |

## 4. 설계

### 4.1 상태 모델 (game.js)
```
Tile  = { id: number, value: number, row: number, col: number,
          mergedFrom?: [id, id], isNew?: boolean }
State = { size: 4, tiles: Tile[], score: number, won: boolean,
          keepPlaying: boolean, over: boolean, nextId: number }
```
- 타일에 고유 `id`를 두어 렌더러가 같은 DOM 요소를 이동시킬 수 있게 한다(애니메이션용).
- 격자 조회는 `toGrid(state) → (Tile|null)[4][4]` 헬퍼로 계산.

### 4.2 공개 함수 (모두 순수 함수, 입력 state를 변경하지 않고 새 객체 반환)
| 함수 | 설명 |
|------|------|
| `createGame(rng = Math.random)` | 빈 보드 + 타일 2개 |
| `slideLine(values: number[]) → { line: number[], gained: number }` | 한 줄(길이 4)을 **왼쪽**으로 밀고 합침. 테스트 핵심 단위 |
| `move(state, dir, rng = Math.random) → { state, moved: boolean, gained: number }` | dir ∈ `'up'|'down'|'left'|'right'`. moved=false면 원래 state 그대로 반환 |
| `addRandomTile(state, rng)` | 빈 칸 하나에 2(rng<0.9)/4 생성 |
| `canMove(state) → boolean` | 빈 칸 있거나 인접 동일 값 있으면 true |
| `hasWon(state)` | 값 2048 이상 타일 존재 |
| `serialize(state) → object` / `deserialize(obj) → State \| null` | 이어하기 저장용. 보드는 4×4 숫자 배열(0=빈칸)로 저장. `deserialize`는 크기·값(0 또는 2의 거듭제곱)·점수(0 이상 정수) 검증 실패 시 `null` |

- 되돌리기는 main.js가 이동 직전 state를 한 개만 보관하는 방식으로 구현(순수 state가 불변이므로 참조 보관으로 충분).

- `rng` 주입으로 테스트 시 결과를 고정할 수 있게 한다.

### 4.3 이동·합치기 알고리즘
1. 방향별로 4개의 줄을 뽑는다. 줄은 **이동 방향 쪽 끝이 인덱스 0**이 되도록 정렬
   (left: 행 그대로, right: 행 역순, up: 열 위→아래, down: 열 아래→위).
2. 각 줄에 `slideLine` 적용:
   - 0 제거 → 앞에서부터 순회, 현재 값과 다음 값이 같으면 합쳐 결과에 넣고 **두 칸 건너뜀**(재합치기 방지), 아니면 그대로 넣음 → 뒤를 0으로 채움.
   - `gained` = 합쳐진 값들의 합.
3. 원래 방향으로 되돌려 배치. 타일 단위 버전에서는 합쳐진 새 타일에 `mergedFrom`, 원래 두 타일의 최종 좌표(애니메이션 목적지) 기록.
4. 하나라도 위치/값이 바뀌면 `moved=true` → 점수 가산, `addRandomTile`, `won`/`over` 갱신.
5. `over = !canMove(state)`. `won`은 처음 2048이 생길 때 true, `keepPlaying`이면 승리 오버레이 억제.

### 4.4 렌더링 (main.js)
- 보드 배경 칸 16개는 CSS grid로 고정 생성, 타일은 별도 레이어에 `position:absolute` + `transform: translate(col*step, row*step)`로 배치.
  - `step`은 CSS 변수(`--cell`, `--gap`)로 계산 → `calc()` 사용, JS는 `--x`/`--y`(0~3 정수)만 설정.
- 렌더 순서: ① 기존 id 타일은 새 좌표로 transform 변경(슬라이드) ② 합쳐진 원본 타일은 목적지로 이동 후 제거 ③ 새/합쳐진 타일은 `tile-new`/`tile-merged` 클래스로 등장.
- 점수 `+N` 표시는 점수 박스 안에 임시 span 추가 → `animationend`에서 제거.
- 입력 잠금 없음: 새 입력이 오면 진행 중 애니메이션 요소를 즉시 정리하고 최신 state로 다시 그림.
- 타일 색: 값별 클래스 `tile-2` … `tile-2048`, 그 이상은 `tile-super`. 4자리 이상은 글자 크기 축소(`tile-len-4`, `tile-len-5`).

### 4.5 입력
- 키보드: `keydown`을 **보드가 포커스이거나 document 전체**에서 수신하되, 오버레이가 열려 있거나 포커스가 버튼일 때 Space/Enter는 가로채지 않음. 방향키 처리 시 `preventDefault()`로 iframe/페이지 스크롤 방지. 수정자 키(Ctrl/Alt/Meta) 조합은 무시.
- 스와이프: 보드 요소에 `pointerdown`/`pointerup`(+`pointercancel`). 이동 거리 ≥ 24px이고 주 축 성분이 큰 쪽으로 방향 결정. 마우스 드래그도 동일하게 동작.
- 보드 클릭/탭 시 보드에 포커스 → 이후 키 입력 수신(iframe 내부에서 특히 필요).

## 5. UI / 레이아웃

### 5.1 화면 구성 (위→아래, 최대 폭 480px 가운데 정렬)
```
[ 2048 (h1) ]                 [ 점수 | 최고 ]
[ 설명 한 줄: "같은 숫자를 합쳐 2048을 만드세요" ]   [ 되돌리기 ] [ 새 게임 ]
┌───────── 보드 (정사각) ─────────┐
│  (타일)       오버레이(승리/게임오버) │
└──────────────────────────────┘
[ 조작 안내: 방향키·WASD / 스와이프 ]
<div class="sr-only" aria-live="polite">  (스크린 리더 안내)
```
- 색상: 헤더/버튼 강조 `--accent: #2458d6`(다크 `#7aa2ff`), 배경 라이트 `#ffffff` / 다크 `#16181c`, 보드 배경 `--bg-subtle` 계열, 글꼴은 블로그와 동일한 시스템 한글 스택.
- 타일 색: **원작 2048 색상표**(베이지 → 주황 → 빨강 → 노랑 계열). 참고값: 2 `#eee4da`, 4 `#ede0c8`, 8 `#f2b179`, 16 `#f59563`, 32 `#f67c5f`, 64 `#f65e3b`, 128 `#edcf72`, 256 `#edcc61`, 512 `#edc850`, 1024 `#edc53f`, 2048 `#edc22e`, 그 이상 `#3c3a32`. 2·4는 어두운 글자, 8 이상은 흰 글자. 보드 배경 `#bbada0`, 빈 칸 `rgba(238,228,218,0.35)`.
  - 글자 대비: 2·4 타일 글자는 원작 `#776e65`보다 진한 `#5c534a` 이상을 써서 4.5:1 확보. 8~64처럼 흰 글자 대비가 낮은 타일은 글자를 굵게(700+) 하고 큰 글자 기준(3:1) 이상을 확인.
  - 다크 모드: 페이지 배경·글자·점수판·버튼만 블로그 다크 톤으로 바꾸고, 보드/타일은 원작 색을 유지하되 보드 배경만 약간 어둡게(`#8f8276` 등).
- 점수판·버튼 강조색은 블로그 파랑(`--accent`)을 그대로 쓴다.

### 5.2 반응형
- 보드 크기: `width: min(100%, 440px)`, `aspect-ratio: 1`. 셀/간격은 보드 폭 기준 `--gap: clamp(6px, 2.5vw, 12px)`.
- 좌우 여백 16px. 375px 폭에서 보드 ≈ 343px, 가로 스크롤 없음(`overflow-x` 발생 요소 없음, 긴 텍스트 줄바꿈).
- 타일 글꼴 크기는 보드 폭 기준 `clamp()`(컨테이너 쿼리 `cqi` 사용 가능, 미지원 시 vw 폴백).
- 높이가 낮은 iframe(예: 520px) 에서도 보드 전체가 보이도록 제목/설명 영역을 컴팩트하게 유지.

### 5.3 스와이프 시 페이지 스크롤 방지
- 보드 요소에 `touch-action: none;` → 보드 위 제스처는 브라우저 스크롤/줌을 하지 않음. 보드 밖은 정상 스크롤.
- `overscroll-behavior: contain`을 body에 지정해 iframe 내부 스크롤이 부모로 번지는 것 완화.
- 보조로 보드 위 `touchmove` 리스너를 `{ passive: false }`로 등록해 `preventDefault()`(구형 iOS 대비).
- 텍스트 선택 방지: 보드에 `user-select: none`.

## 6. 블로그 삽입(Embed) 방안

### 카드 문구 초안
- 제목: **2048**
- 설명: "같은 숫자 타일을 밀어 합쳐 2048을 만드는 퍼즐 게임. 방향키·WASD·스와이프로 플레이하세요."
- 링크: "새 창에서 크게 하기 →" (`apps/2048/`)

### 추천: iframe (+ 새 창 링크)
- 이유: 게임은 직접 해 보는 것이 핵심이라 카드에서 바로 플레이 가능한 iframe이 포트폴리오 가치가 크다. 순수 정적 파일이고 같은 오리진이라 보안·경로 문제 없음.
- 조건: `<iframe src="apps/2048/" title="2048 게임" loading="lazy" width="100%" height="560">` 형태, 테두리 없음. 모바일에서 보드 스와이프가 카드 안에서 동작하고 보드 밖에서는 페이지 스크롤 가능(5.3).
- 보완: iframe 안에서 방향키는 포커스(보드 탭/클릭) 후 동작한다는 안내를 조작 안내 문구에 포함. 메인 페이지가 무거워지는 게 걱정되면 미리보기 이미지(`preview.png`) + 클릭 시 iframe 로드(lazy) 방식으로 대체 가능.

## 7. 검증 체크리스트 (Review 단계)

### 7.1 `slideLine` 단위 케이스 (왼쪽 기준)
| 입력 | 결과 | gained |
|------|------|--------|
| `[2,2,2,2]` | `[4,4,0,0]` | 8 |
| `[2,2,4,0]` | `[4,4,0,0]` | 4 (새로 생긴 4가 기존 4와 재합쳐지면 안 됨) |
| `[4,4,8,8]` | `[8,16,0,0]` | 24 |
| `[2,0,0,2]` | `[4,0,0,0]` | 4 |
| `[0,0,0,2]` | `[2,0,0,0]` | 0 |
| `[2,2,2,0]` | `[4,2,0,0]` | 4 (앞쪽부터 합침) |
| `[4,2,2,0]` | `[4,4,0,0]` | 4 |
| `[2,4,8,16]` | `[2,4,8,16]` | 0, moved=false |
| `[0,0,0,0]` | `[0,0,0,0]` | 0 |

### 7.2 방향·상태 규칙
- [ ] 오른쪽 이동 `[2,2,2,0]` → `[0,0,2,4]`(이동 방향 쪽부터 합침), 위/아래도 열 기준 동일
- [ ] 변화 없는 이동은 새 타일 생성·점수 변화 없음
- [ ] 새 타일 비율: rng 고정 시 `<0.9` → 2, 그 외 → 4
- [ ] 시작 시 타일 정확히 2개
- [ ] 게임 오버: 꽉 찬 `[[2,4,2,4],[4,2,4,2],[2,4,2,4],[4,2,4,2]]` → over=true / 한 곳만 인접 동일 값이면 false
- [ ] 2048 생성 시 승리 오버레이 1회, 계속하기 후 진행 가능·재표시 없음
- [ ] 최고 점수: 새로고침 후 유지, localStorage 차단(시크릿/예외) 환경에서도 오류 없이 동작
- [ ] `game.js`에 DOM/`window`/`localStorage` 참조 없음

### 7.3 UI/환경
