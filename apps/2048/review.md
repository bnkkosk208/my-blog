# 2048 리뷰

## 요약
**판정: 통과.** spec 7장 항목은 모두 통과했고, 실패한 항목은 없습니다. 실제 기기나 도구가 필요한 2개 항목(실기기 터치 스크롤, reduced-motion 실제 동작)만 부분 미확인입니다. 차단 수준의 버그는 없으며, 발견한 문제는 모두 심각도 "낮음"입니다.

검증 환경: Node v24.19.0로 로직 테스트 56건(전부 통과). 브라우저는 `http://localhost:8000/apps/2048/`(응답 200)에서 실제 키 입력·마우스 드래그·클릭과 iframe 안의 합성 이벤트로 테스트했습니다. 폭은 375·768·1280px에 더해 iframe 300·360px로 확인했습니다. 테마는 라이트/다크, 그리고 블로그 `theme` 값(`light`/`dark`)을 둘 다 적용해 봤습니다.

### 7.2 방향·상태 규칙
- ✅ 오른쪽 이동: `[2,2,2,0]`→`[0,0,2,4]`, `[2,2,2,2]`→`[0,0,4,4]`. 위/아래도 열 기준 `[2,2,2,0]`→`[4,2,0,0]`/`[0,0,2,4]`, 아래 방향 `[8,8,16,16]` 열→`[0,0,16,32]`(Node).
- ✅ 변화 없는 이동: `move`가 같은 state 객체를 돌려주고 moved=false, gained=0. 브라우저에서도 타일 수와 점수가 그대로이고 되돌리기 대상도 유지됩니다.
- ✅ 새 타일 값: rng 0.89→2, 0.9→4, rng≈1에서도 인덱스가 범위를 벗어나지 않습니다(`Math.min` 처리). 무작위 1만 개 중 4의 비율은 0.099입니다.
- ✅ 시작 타일: `createGame` 200회 모두 서로 다른 칸에 정확히 2개.
- ✅ 게임 오버: 체크무늬 보드는 `canMove`=false, 가로 또는 세로로 한 쌍만 같아도 true. 브라우저에서 마지막 한 수 뒤 "게임 오버·최종 점수 516" 오버레이가 뜨고 `over:true`로 저장됩니다.
- ✅ 승리: 1024+1024 이동 시 "2048 달성!"이 뜨고 [계속하기]에 포커스가 갑니다. 계속하기 후 이동·되돌리기·새로고침을 해도 다시 뜨지 않습니다. 오버레이가 열려 있는 동안 방향키 입력은 무시됩니다.
- ✅ 최고 점수: 새로고침 후 유지됩니다. `localStorage` 접근 시 SecurityError를 던지게 만든 환경에서도 오류 없이 플레이·새 게임이 되고, 최고 점수는 메모리에서 갱신됩니다.
- ✅ `game.js`에 `document`/`window`/`localStorage` 참조가 없습니다(grep 0건).

### 7.3 UI/환경
- ✅ 방향키·WASD(대문자 `W`, 한글 IME 상태 `code=KeyD` 포함)·마우스 드래그 스와이프·터치 pointer 스와이프 모두 동작합니다. 24px 미만 드래그는 무시되고, Ctrl 조합과 Space는 가로채지 않습니다. 방향키는 `preventDefault` 처리되어 부모 페이지(3000px 높이)가 스크롤되지 않습니다.
- ✅ 375px: 보드 343px, `scrollWidth`=375로 가로 스크롤 없음. 300·360·768·1280px에서도 넘치는 요소가 없습니다.
- ⚠️ 모바일 스와이프 시 스크롤/당겨서 새로고침 방지: 코드상으로는 보드에 `touch-action:none`, `touchmove` `{passive:false}`로 `preventDefault`, body에 `overscroll-behavior:contain`이 적용되어 있고 합성 터치 pointer 스와이프도 동작했습니다. 다만 실기기 터치 제스처로는 확인하지 못했습니다.
- ✅ 라이트/다크: 시스템 설정(`colorScheme` 에뮬레이션)과 블로그 `theme` 값 모두 반영되고, `storage` 이벤트로 실시간 전환도 됩니다. 대비 계산 결과: 2·4 타일 6.0/5.8:1, 갈색 글자 타일 4.9~10.3:1, 64(흰 글자) 3.19:1, 강조 버튼 6.1(라이트)/6.9(다크):1, 보조 글자 6.1/6.95:1.
- ⚠️ 애니메이션: 이동 시 `transform` 전환(ghost 포함), `tile-pop`·`tile-appear`·`float-up` 애니메이션이 실행되는 것을 `getAnimations()`로 확인했습니다. reduced-motion은 도구로 에뮬레이션할 수 없어 CSSOM에서 `@media (prefers-reduced-motion: reduce)` 규칙이 파싱되는 것만 확인했습니다.
- ✅ 접근성: Tab 순서는 (비활성 되돌리기 건너뜀) → 새 게임 → 보드이고, `:focus-visible` 3px 포커스 링이 보입니다. 보드 속성은 `role=application`·`aria-label`·`tabindex=0`·`aria-describedby=help`입니다. `aria-live=polite` 영역에 "점수 4, 이동 +4", 승리, 게임 오버, 되돌리기 안내가 채워지는 것을 확인했습니다(실제 스크린 리더 낭독은 확인하지 않음).
- ✅ iframe 360×560: 문서 높이가 정확히 560px로 잘림이 없고 보드는 328px입니다. 부모 페이지에서 보드를 실제로 클릭한 뒤 방향키를 누르면 이동하고, 부모·iframe 모두 스크롤되지 않습니다.
- ✅ 콘솔 에러 없음. 모든 경로가 상대 경로(`./style.css`, `./main.js`, `./game.js`)이고, 직접 로드 시 요청은 모두 200/304입니다.

### 7.4 되돌리기·이어하기
- ✅ 이동 후 되돌리기: 보드와 점수가 직전 상태로 돌아가고 버튼이 비활성화됩니다. 두 번째 클릭은 아무 동작도 하지 않고, 최고 점수는 유지됩니다.
- ✅ 유효한 이동 후 변화 없는 이동을 해도 되돌리기가 활성 상태로 남고, 되돌리면 유효 이동 직전 보드로 돌아갑니다.
- ✅ 게임 오버 후 오버레이의 [되돌리기]를 누르면 오버레이가 닫히고 보드에 포커스가 가며, 이어서 이동할 수 있습니다.
- ✅ 새로고침 후 같은 보드·점수가 복원되고 되돌리기는 비활성입니다.
- ✅ 손상값 `"abc"`, 5×5, 값 3, `null`, `[]`, `grid:"x"`, 음수 점수, 빈 문자열 → 모두 오류 없이 새 게임(타일 2개, 점수 0)이 시작되고 정상 상태로 다시 저장됩니다. Node에서는 1, `'2'`, `null` 칸, 2^31, 소수 점수, 잘못된 flag, 빈 보드도 모두 `null`을 반환했습니다.

## 발견한 문제

1. **낮음 — 저장된 점수가 최고 점수를 그대로 올림** (`main.js:350-353`)
   - 재현: `localStorage['2048-state']`에 `score:20000`인 유효한 보드를 넣고 새로고침하면 최고 점수가 20000이 됩니다.
   - 정상 플레이에서는 문제가 없습니다. 다만 수동 조작이나 다른 버전이 남긴 저장값이 최고 점수로 들어갑니다. 의도된 동작이라면 그대로 둬도 되고, 아니라면 로드 시 best 갱신을 빼는 방안이 있습니다.
2. **낮음 — 되돌리기 버튼을 누르면 키보드 포커스가 사라짐** (`main.js:203-207`, `282-293`)
   - 재현: Tab으로 [되돌리기]에 포커스를 두고 Enter를 누르면 버튼이 `disabled`로 바뀌면서 포커스가 body로 빠집니다.
   - 방향키는 document에서 받기 때문에 게임은 계속되지만, Tab 위치가 처음으로 돌아갑니다. 제안: `undo()`에서 포커스가 되돌리기 버튼에 있었다면 보드로 `focus({preventScroll:true})`.
3. **낮음 — 오버레이 dialog에 포커스 가두기와 `aria-modal`이 없음** (`index.html:56`)
   - 재현: 승리/게임 오버 오버레이 상태에서 Tab을 누르면 오버레이 밖의 [되돌리기]/[새 게임]으로 이동합니다. 두 버튼 모두 정상 동작하므로 기능 문제는 아닙니다.
   - 제안: `aria-modal="true"`를 추가하거나, `role="dialog"` 대신 `role="alertdialog"` 또는 단순 영역으로 두는 방안을 검토.
4. **낮음 — 높이 520px iframe에서 세로 스크롤 22px 발생** (`style.css:251`)
   - 재현: iframe 360×520에서 문서 높이가 542px이 됩니다. 보드는 전부 보이지만(보드 아래 끝 462px), 하단 안내 문구가 조금 잘려 스크롤이 생깁니다.
   - spec 5.2의 "보드 전체가 보이도록" 조건은 충족합니다. Embed에서 권장값 560px을 쓰면 문제없습니다.
5. **낮음(디자인) — 64 타일만 흰 글자** (`style.css:396`)
   - 흰 글자 대비 3.19:1로, 굵은 큰 글자 기준 3:1은 충족합니다. 하지만 주변 8~32·128+ 타일은 갈색 글자라 64만 튀어 보입니다. 갈색 `#3b2f25`를 쓰면 4.07:1입니다. 일관성을 원하면 갈색으로 바꾸는 것도 방법입니다.

## 참고 사항
- **Build에서 spec과 다르게 한 부분 평가**
  - 8·16·32·128~2048 타일 글자를 `#3b2f25`로 변경: **합리적.** 흰 글자일 때 대비가 1.5~2.6:1로 spec 5.1의 "큰 글자 3:1"을 충족하지 못합니다. 갈색으로 바꾸면 4.9~8.5:1이라 오히려 spec의 접근성 의도에 맞습니다.
  - 계속하기 후 되돌려도 `keepPlaying` 유지: **합리적.** F8 "계속하기 후에는 다시 뜨지 않음"과 F13 "won/over 모두 이전 상태로"가 충돌하는데, 사용자가 이미 고른 선택을 존중하는 쪽이 자연스럽습니다. 브라우저에서도 되돌리기와 새로고침 후 재표시가 없음을 확인했습니다.
  - `deserialize`가 빈 보드를 손상으로 보고 `over`를 재계산: **합리적.** 정상 게임에서는 빈 보드가 나올 수 없고, `over`를 보드에서 다시 계산하면 저장값 불일치(움직일 수 있는데 `over:true`)를 막을 수 있습니다. Node로 두 경우 모두 확인했습니다.
- **코드 리뷰 결과 문제 없음**
  - XSS: 타일·점수·안내에 모두 `textContent`를 쓰고 `innerHTML`은 쓰지 않습니다.
  - 메모리: ghost 요소, `+N` span 모두 제거를 확인했습니다. 연속 7회 입력 후 400ms가 지나면 ghost 0, 1.2초 뒤 `score-add` 0이고, 이벤트 리스너는 `init`에서 한 번만 등록합니다.
  - 경쟁 상태: 7회 연속 입력 후 DOM 타일 위치가 겹치지 않았고, DOM 보드와 저장된 보드가 일치했습니다.
  - `localStorage`: 모든 접근이 try/catch로 감싸져 있고, 인라인 테마 스크립트도 마찬가지입니다.
- **테스트 중 참고**: 기존 탭(tab-4)에서 사용자 조작으로 보이는 클릭·키 입력이 섞여 들어와, 해당 탭 결과는 판정에서 제외했습니다. 이후 검증은 별도 백그라운드 탭에서 한 번의 스크립트 안에 끝나도록 진행했습니다. 테스트 전 원래 값은 `2048-state`·`2048-best` 없음, `theme`=`dark`였습니다. 종료 시 `2048-state`·`2048-best`를 삭제했고 `theme`은 바꾸지 않았습니다(`dark` 유지). viewport는 desktop 프리셋으로 되돌렸고, Node 임시 테스트 스크립트도 삭제했습니다.

### 남은 문제
- **낮음(참고)**: 로드 시에는 최고 점수를 올리지 않지만, 손으로 큰 점수를 넣은 저장값으로 **한 번이라도 이동하면** `updateBest()`가 그 점수를 최고 점수로 기록합니다. 수정 지침("실제 이동으로 점수가 오를 때만 갱신")대로의 동작이라 그대로 둬도 됩니다.
- **낮음(기존 4번, 수정 제외)**: 높이 520px iframe에서 22px 세로 스크롤. Embed에서 560px을 쓰면 해당 없습니다.
- **미확인**: 3b(실제 Tab 순환), 5의 콘솔 오류 확인. 서버를 다시 띄운 뒤 확인이 필요합니다.

### 정리 상태
- 재검증용 탭(tab-6, tab-7)은 닫혔거나 제가 닫았습니다. viewport 에뮬레이션은 쓰지 않았습니다.
- **정리하지 못한 값**: 서버가 멈춘 뒤라 `localhost:8000` 오리진에 접근할 수 없어, 테스트로 넣은 `localStorage['2048-state']`(1024 타일 두 개짜리 보드)를 지우지 못했습니다. `2048-best`는 없음, `theme`은 `dark`로 원래 값 그대로입니다. 서버가 다시 뜨면 `localStorage.removeItem('2048-state')`를 실행해야 원래 상태(없음)로 돌아갑니다.
