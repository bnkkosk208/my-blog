# Plan 서브에이전트 지침 — 런던 여행 앱 v7: 날짜별 날씨 예보

## 역할
Plan 단계 담당. 코드는 작성하지 않는다. **간결하게**(70줄 이내).

## 수정 허용 범위
- `apps/london-trip/spec.md` 맨 끝에 **"## 18. 날짜별 날씨 예보 (v7)"** 절 추가만. 기존 1~17장은 수정하지 않는다. 다른 파일은 건드리지 않는다.

## 사용자 요구
"날짜와 함께 날씨(예보)도 같이 표시해줘."

## 고려 사항
- 오늘은 2026-10-14, 여행 2026-10-16~10-23. GitHub Pages 정적 사이트, 서버·API 키 보관 불가.
- 예보는 런타임 외부 요청이 필수 → 지금까지 "외부 요청 없음" 원칙의 **예외**로 명시하고 사용자 승인 항목에 올린다.
- 출처 후보 비교 후 기본안: **Open-Meteo**(`https://api.open-meteo.com/v1/forecast`, API 키 불필요, CORS 허용, 최대 16일 예보, `timezone=Europe/London`, daily: weather_code, temperature_2m_max/min, precipitation_probability_max 등; 비상업 무료, 출처 표기 "Weather data by Open-Meteo.com" CC BY 4.0). 다른 후보(MET Norway 등)는 짧게만. 엔드포인트·파라미터·응답 필드는 Build에서 실제 응답으로 확인하도록 지시.
- 위치: 런던 중심(소호, 대략 51.51, -0.13). 10/20 리치몬드(골프)·10/16 도착 등 날짜별 다른 위치가 필요한지 판단(기본안: 런던 하나). 서울/부산 날씨 필요 여부(기본안: 불필요).
- 표시 위치: 날짜 탭(Day N 아래 아이콘+최고/최저)과 일자 요약 카드(날씨 설명, 최고/최저, 강수확률, 우산 권장 등). 360px에서 날짜 탭이 넘치지 않게. 날씨 코드 → 한국어 설명·이모지 매핑표(WMO 코드).
- 시간별 예보(일정 카드 시간대 강수확률 등)는 범위에 넣을지 사용자 결정 항목으로(기본안: 일 단위만).
- 캐시·갱신: localStorage 캐시(예: 3시간 TTL), 오프라인/실패 시 마지막 캐시 + "업데이트 시각" 표시, 실패해도 앱 정상. 예보 범위 밖(16일 초과, 여행 후)은 숨김. 여행 중 지난 날짜는 예보 대신 표시 안 함 또는 마지막 값.
- 블로그 iframe·서비스 워커(sw.js는 fetch 가로채지 않음)와의 관계, 프라이버시(사용자 위치 사용 안 함, 고정 좌표만).
- 변경 파일 범위(예: 새 `weather.js` + app.js/style.css/index.html), localStorage 키.
- 완료 기준(Review 체크리스트): 실제 API 응답 확인, fetch 실패·오프라인 시뮬레이션, 캐시 TTL, 360/375px, 회귀(65행·금액·알림·자동 이동·한국 시각·사진·스와이프·자동 완료).
- **사용자 결정 필요** 표(기본안 포함).
