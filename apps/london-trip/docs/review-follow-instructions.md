# Review 서브에이전트 지침 — 런던 여행 앱 v3: 현재 위치 자동 이동

## 역할
Review 단계 담당. Build와 분리된 독립 검증자다. 구현자 보고를 믿지 말고 직접 확인한다.

## 수정 허용 범위
- `apps/london-trip/review.md`: 기존 내용 유지, 맨 끝에 **"## v3 현재 위치 자동 이동 리뷰"** 절 추가.
- 문제를 고칠 때만: `apps/london-trip/app.js`, `style.css`, `index.html`
그 외 파일은 수정하지 않는다. git 커밋하지 않는다.

## 검증 기준
- `spec.md` 14장 체크리스트 + 끝의 "14.x 사용자 확정"(기본안: 보류 3분, 여행 전 Day 1 r02, 다른 탭은 버튼만·앱 복귀 시 일정 탭, 여행 후 Day 8 맨 위, 앱 복귀 시 보류 무시).
- 회귀: 65행, 요약 금액, 알림 발사(r30 15:00:10Z, `TripTime.now` 고정), 완료/메모/내 일정, 375px 가로 스크롤 없음, iframe 안에서 부모 페이지 스크롤 없음.
- 코드 리뷰: 이벤트 리스너·타이머 누수, 스크롤 루프(자동 스크롤이 사용자 스크롤로 오인되어 보류가 걸리는지), 입력 중 이동, 성능.

## Build가 spec과 다르게 했다고 보고한 점 (타당성 판단)
1. 앱 복귀 시 일정 탭 자동 전환은 여행 중에만
2. 체크박스·버튼 포커스는 "입력 중"으로 보지 않음
3. "지금으로" 버튼은 보류·이동 금지 무시
4. lastDay는 Intl 미지원 시에만 사용
5. 여행 전 r02 숨김 시 대체 항목, 여행 후/대상 없음은 맨 위
6. 보류 종료 후 위치를 벗어나 있으면 타이머가 복귀
7. "지금으로" 버튼을 토스트 컨테이너 맨 위에 배치
8. 검증용 전역 `window.TripApp` 추가

## 특히 판단할 점
- **알림 패널이 열려 있으면 자동 이동이 계속 멈춘다**는 Build 보고. 패널 열림 상태가 저장·유지되는 구조라면 사용자가 패널을 연 채 두면 "항상 현재 위치" 요구가 깨진다. 사용자 요구("항상 그 위치로 이동해 있게")에 맞게, 패널 열림만으로는 영구 차단하지 말고(예: 패널 안 입력 포커스·select 사용 중만 차단, 또는 보류 규칙 적용) 고치는 것이 타당하면 고쳐라.
- 콘솔의 `about:srcdoc ... TripTime is not defined` 기록은 이전 리뷰 단계의 임시 iframe 잔재로 보인다. 새 탭에서 다시 확인해 앱 원인이 아닌지 확정.
