# Plan 서브에이전트 지침 — 런던 여행 앱 v6: 시간 경과 시 자동 완료 체크

## 역할
Plan 단계 담당. 코드는 작성하지 않는다. **간결하게**(60줄 이내).

## 수정 허용 범위
- `apps/london-trip/spec.md` 맨 끝에 **"## 17. 시간 경과 자동 완료 (v6)"** 절 추가만. 기존 1~16장은 수정하지 않는다. 다른 파일은 건드리지 않는다.

## 사용자 요구
"시간이 지나면 완료 체크 자동 체크해줘."

## 현재 구조 (app.js, store.js, time.js 확인)
- 완료 체크: `london-trip:v1:done` `{id:true}`, 원본·사용자 일정 모두.
- 런던 시각 `TripTime`, 시각 변환 `toEpoch(date, hhmm, tz)`(r02 등 tz 혼재 행 처리), 1분 타이머·visibilitychange·pageshow에서 `tick`.
- 알림(13장)은 완료 항목 건너뜀, 요약은 완료 수 표시, 자동 이동(14장)은 진행 중/다음 카드.

## 계획에 담을 내용
1. **판정 기준**: 종료 시각(end)이 지나면 완료. 종료 없는 항목(사용자 일정 시작만, r66 등) 처리 — 예: 시작 + 소요(durationMin) 또는 시작 시각 기준, 혹은 제외. 시각은 epoch 비교(기기 시간대 무관), r02/r66 tz 처리.
2. **저장 방식 비교 후 기본안**: (a) `done`에 직접 기록 vs (b) 저장하지 않고 렌더 시 계산(자동 완료 표시) + 사용자가 해제한 항목만 `undone` 예외로 저장. 사용자가 자동 완료를 **수동으로 해제하면 다시 자동 체크되지 않아야** 한다. 사용자 일정의 시간을 미래로 바꾸면 어떻게 되는지.
3. **표시**: 수동 완료와 자동 완료 구분 여부(예: "자동" 작은 배지/툴팁), 접근성 문구.
4. **실행 시점**: 첫 로드, tick(1분), 복귀 시. 여행 전에는 아무 것도 체크 안 됨, 여행 후 접속 시 전체 자동 완료.
5. **기능 설정**: 자동 완료 켜기/끄기 토글 필요 여부(기본 켬).
6. **연동**: 일자 요약 완료 수, 날짜 탭 진행 표시, 알림(이미 지난 항목은 원래 안 울림), 자동 이동 대상(완료 카드 흐림과 "지금/다음"), 이 날 체크 초기화·전체 초기화·백업 내보내기/가져오기와의 관계.
7. 변경 파일 범위, localStorage 키 추가 여부.
8. 완료 기준(Review 체크리스트, `TripTime.now` 고정으로 확인).
9. **사용자 결정 필요** 표(기본안 포함).
