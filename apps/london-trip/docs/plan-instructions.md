# Plan 서브에이전트 지침 — 런던 여행 일정관리 웹앱

## 역할
너는 Plan 단계 담당이다. 코드를 작성하지 말고 **계획 문서 한 개만** 작성한다.

## 작성할 파일 (이 파일 하나만 생성/수정)
- `apps/london-trip/spec.md`

다른 파일은 절대 만들거나 수정하지 않는다.

## 입력 자료
- 원본 엑셀(사용자 제공): `런던_여행_시간대별_일정표_소호숙소버전_v7.xlsx`
- 엑셀 전체 내용을 텍스트로 덤프한 파일: `apps/london-trip/docs/source-dump.txt` (이것을 읽어라)
  - 시트: 런던일정(10/16~10/23 시간대별 65행), 범례, 식당예약방법, 뮤지컬추천, 골프장추천
- 참고용 기존 앱 구조: `apps/2048/spec.md` (형식·분량 참고), 블로그 규칙 `CLAUDE.md`

## 사용자 요구
"이 일정파일을 활용한 **일자별 일정관리 모바일웹 홈페이지**를 만들어줘."

## 프로젝트 제약 (CLAUDE.md)
- HTML/CSS/JavaScript만 사용. 빌드 도구 없음. 외부 라이브러리 최소화(CDN은 허용).
- 앱은 `apps/london-trip/` 폴더 안에서 자체 완결. GitHub Pages(정적 호스팅)로 배포됨.
- 모바일 우선, 데스크톱에서도 깨지지 않을 것. 블로그 메인에 iframe 카드로 삽입될 예정.

## spec.md에 반드시 담을 내용
1. **개요** — 무엇을 만드는지 2~3줄.
2. **화면 구성** — 모바일 기준 화면/섹션 설명. 최소한:
   - 날짜 탭(10/16~10/23, 요일·Day N 표시), 오늘 날짜면 자동 선택
   - 선택한 날의 타임라인(시작~종료, 소요, 활동/이동 구분 색상, 이동수단, 예약필요 배지, 예상 비용)
   - 항목 펼치기 시 비고(주소/링크), 주변 식당·카페 추천 표시
   - 일정관리 기능: 항목 완료 체크, 개인 메모, (선택) 사용자 일정 추가/수정/삭제 — 저장은 localStorage, 원본 데이터는 불변
   - 현재 진행 중 항목 하이라이트(여행 당일, 런던 시간 기준 — 시간대 처리 방법 명시)
   - 부가 정보 탭/섹션: 예약 체크리스트(예약필요 항목 모음), 식당 예약방법, 뮤지컬 추천, 골프장 추천
   - 일자별 요약(활동 수, 예상 교통비 등 계산 가능한 범위만)
3. **데이터 설계** — 엑셀 → `data.js`(또는 JSON) 변환 방식과 스키마(필드명, 타입). 런던일정 65행을 빠짐없이 옮길 것. 링크 텍스트(예: `tfl.gov.uk`)를 클릭 가능한 URL로 만드는 규칙.
4. **파일 구조** — `apps/london-trip/` 아래 파일 목록과 각 역할.
5. **localStorage 키 설계** 및 초기화(리셋) 방법.
6. **디자인 방향** — 색상 토큰, 다크모드, 터치 타깃 크기, 폰트.
7. **엣지 케이스** — 10/23처럼 시작시간이 `-`인 행, 자정 근처, 여행 기간 밖 접속 시 동작 등.
8. **개인정보 주의** — 원본에 숙소 상세 주소(동·호수 포함)가 있다. 공개 블로그에 그대로 노출할지 여부를 "사용자 결정 필요" 항목으로 표시하고 기본안(예: 거리명·우편번호 수준만 표기)을 제안.
9. **원본 데이터 불일치 메모** — 덤프에서 발견되는 모순을 목록화(예: 뮤지컬 시트는 10/19(월) 관람이라 적혀 있으나 일정표는 10/20(화), 식당예약 시트의 Odette's가 일정표에 없음 등). 수정하지 말고 표시만.
10. **완료 기준(체크리스트)** — Review 단계에서 확인할 항목.
