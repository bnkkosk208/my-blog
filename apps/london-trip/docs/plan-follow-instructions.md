# Plan 서브에이전트 지침 — 런던 여행 앱 v3: 현재 위치 자동 이동

## 역할
Plan 단계 담당. 코드는 작성하지 않는다. **간결하게**(80줄 이내) 작성한다.

## 수정 허용 범위
- `apps/london-trip/spec.md` 맨 끝에 **"## 14. 현재 위치 자동 이동 (v3)"** 절 추가만. 기존 1~13장은 수정하지 않는다(대체하는 규칙은 14장에 "2.1/2.4를 대체"처럼 명시). 다른 파일은 건드리지 않는다.

## 사용자 요구
"일자, 시간 체크해서 항상 그 위치로 이동해 있게 수정해줘."
→ 앱이 런던 기준 오늘 날짜 탭과 지금 진행 중(없으면 다음) 일정 카드 위치에 **항상** 맞춰져 있어야 한다.

## 현재 동작 (app.js 확인할 것)
- 초기 날짜: 해시 `#day=` → 런던 오늘(여행 기간 내) → lastDay → Day 1.
- 자동 스크롤: 날짜별 1회(`state.autoScrolled`), 사용자가 한 번이라도 스크롤하면(`state.userScrolled`) 다시 안 함.
- 1분 타이머 / visibilitychange에서 하이라이트만 재계산, 탭·스크롤 이동은 하지 않음. 자정 넘김 시 탭 강제 이동 안 함(7장 3번).

## 계획에 담을 내용
1. **이동 시점**: 첫 로드, 탭/앱 복귀(visibilitychange·pageshow), 진행 중 항목이 바뀔 때(1분 타이머), 런던 자정 넘김(날짜 변경).
2. **사용자 조작과 충돌 방지**: 사용자가 다른 날짜 탭을 누르거나 스크롤·펼치기·입력(메모, 바텀시트) 중이면 일정 시간(제안: 마지막 조작 후 N분) 동안 자동 이동 보류 → 이후 다시 현재 위치로 복귀. 입력 포커스·열린 dialog 중에는 절대 이동하지 않음.
3. **"지금으로" 버튼**: 현재 위치에서 벗어났을 때 떠 있는 버튼(44px)으로 즉시 복귀.
4. **뷰 탭**: 일정이 아닌 탭(예약/식당 등)을 보고 있을 때 처리.
5. **여행 기간 밖**: 여행 전에는 Day 1 첫 일정(또는 r02), 여행 후에는 마지막 날 — "현재 위치" 정의.
6. **해시 `#day=…&item=…`(알림 클릭)** 우선순위와의 관계.
7. **스크롤 위치 계산**: 고정 헤더(sticky 탭) 높이 보정, iframe 안에서는 바깥 페이지 스크롤 금지(기존 window.scrollTo 방식 유지), `prefers-reduced-motion`.
8. 변경 파일 범위(app.js, style.css, index.html 정도), localStorage 추가 여부.
9. 완료 기준(Review 체크리스트) — `TripTime.now` 고정으로 확인하는 방법 포함.
10. **사용자 결정 필요** 표: 자동 이동 보류 시간 기본값, 여행 전 동작, 다른 뷰 탭 처리 등. 각각 기본안 제시.
