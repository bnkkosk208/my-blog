# Review 서브에이전트 지침 — 런던 여행 앱 v2: 알림 기능

## 역할
Review 단계 담당. Build와 분리된 독립 검증자다. 구현자 보고를 믿지 말고 직접 확인한다.

## 수정 허용 범위
- `apps/london-trip/review.md`: 기존 내용은 유지하고 맨 끝에 **"## v2 알림 기능 리뷰"** 절을 추가.
- 문제를 발견해 고칠 때만: `apps/london-trip/index.html`, `style.css`, `app.js`, `store.js`, `time.js`, `alarm.js`, `sw.js`

그 외 파일(블로그 루트, `apps/2048/`, `data.js`, `spec.md`, `docs/`, `.gitignore`, `.claude/`)은 수정하지 않는다. git 커밋하지 않는다.

## 검증 기준
- `apps/london-trip/spec.md` 13장, 특히 13.9 체크리스트와 13.10 사용자 확정.
  - 단, "이동 항목 켜기" 기대값은 31이 아니라 **30**이 맞다(r66은 시작 시간이 없어 제외) — Build가 보고한 차이.
- 기존 10장 회귀: 65행, 일자 요약 금액, 완료/메모/내 일정/숨기기/백업, 콘솔 에러 0, 360px 가로 스크롤 없음.
- 코드 리뷰: 시간대 계산(기기 시간대가 KST여도 동작하는지 — 로컬 시간 함수 사용 여부), 중복 발사, 타이머 누수, 저장값 검증, .ics 형식(RFC 5545: CRLF, 75옥텟 접기, 이스케이프, UID/DTSTAMP), sw.js 범위(fetch/캐시/push 없음), XSS.

## Build가 spec과 다르게 했다고 보고한 점 (타당성 판단)
1. 이동 항목 일괄 켜기 30개(r66 제외)
2. 토스트·시스템 알림 문구에 시작 시각 표시(패널은 알림 시각)
3. 시작 시각이 지난 항목을 켜면 울리지 않고 기록만
4. 꺼진 항목에서 시점 select 변경 시 알림 켜짐(안내 문구 있음)
5. SW는 권한 granted + top 창 + https/localhost일 때만 등록
6. .ics VALARM은 알림 켜고 미완료 항목에만
7. 진동은 사용자 활성화 후에만

## 브라우저 검증
- 내장 브라우저 미리보기(`.claude/launch.json`의 `blog`, 포트 8000), `http://localhost:8000/apps/london-trip/`. 캐시 회피용 쿼리(`?v=…`) 사용.
- 블로그 메인 `http://localhost:8000/?v=…`의 london-trip iframe 카드 안에서도 알림 패널 안내가 정상인지 확인.
- `TripTime.now` 고정으로 발사 확인. 모바일(375×812)·다크 모드 확인. 끝나면 뷰포트 복원.
- 테스트 후 `london-trip:` 키 정리, 서비스 워커 등록했으면 해제. `theme`, `2048-*` 키는 건드리지 않는다.
