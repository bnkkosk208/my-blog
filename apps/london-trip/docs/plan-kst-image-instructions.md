# Plan 서브에이전트 지침 — 런던 여행 앱 v4: 한국 시간 + 장소 이미지

## 역할
Plan 단계 담당. 코드는 작성하지 않는다. **간결하게**(100줄 이내).

## 수정 허용 범위
- `apps/london-trip/spec.md` 맨 끝에 **"## 15. 한국 시간 표시 + 장소 이미지 (v4)"** 절 추가만. 기존 1~14장은 수정하지 않는다(대체 규칙은 15장에 명시). 다른 파일은 건드리지 않는다.

## 사용자 요구
"한국 시간도 추가해주고, 장소별로 이미지 참고 자료도 추가로 표시해줘."

## A. 한국 시간
- 헤더 시계: 런던 시각 옆에 한국 시각(Asia/Seoul, `Intl`) 함께 표시. 시차(현재 BST라 +8h, 10/25 이후 GMT면 +9h — 하드코딩 금지) 표기.
- 일정 카드: 런던 시작–종료 옆/아래에 한국 시각 보조 표기(날짜가 바뀌면 `+1일` 등). r02(한국 출발)·r66(한국 도착)처럼 이미 tz가 다른 행 처리. 알림 토스트·다가오는 알림 목록·.ics에 영향이 있는지 명시(.ics는 UTC라 불변).
- 표시 on/off 토글이 필요한지 판단(사용자 결정 항목으로).
- `time.js`의 기존 `toEpoch`/`format` 재사용.

## B. 장소 이미지
- 대상: 일정표의 관광지·장소(예: 대영박물관, 내셔널갤러리, 피카딜리 서커스, 버로우 마켓, 타워브리지, 런던탑, 테이트모던, 런던아이, 코번트가든, 빅벤, 버킹엄궁, 스카이가든, 세인트폴, 켄싱턴궁, 노팅힐, 포토벨로, 차이나타운, 리전트 스트리트, 쇼디치/브릭레인, 리치몬드 파크, 히드로, 웨스트엔드 극장 등). `data.js` schedule 65행을 읽고 **행 id → 장소 매핑표**를 작성. 이동 행은 목적지 이미지를 쓸지/안 쓸지 규칙.
- 이미지 출처 방식 비교 후 기본안 제시:
  1. **런타임 위키백과 REST API** `https://{lang}.wikipedia.org/api/rest_v1/page/summary/{title}`의 `thumbnail`/`originalimage`(CORS 허용, 라이선스는 위키미디어 공용) — 카드 펼칠 때 지연 로드, 캐시(sessionStorage/localStorage), 실패 시 숨김, 출처 링크(위키백과 문서) 표시. 외부 요청 발생(지금까지 '외부 요청 없음' 원칙의 예외로 명시).
  2. 이미지 파일을 저장소에 직접 포함(라이선스·저작자 표기 필요, 용량 증가).
  3. 이미지 대신 Google 이미지 검색 링크만.
  - 위키백과 문서 제목은 실제 존재하는 영문 제목만 사용(예: `British_Museum`, `Tower_Bridge`). 제목은 Build 단계에서 API로 실제 확인하도록 지시.
- 식당·카페·뮤지컬 극장·골프장 이미지는 범위에 넣을지 판단(사용자 결정 항목). 기본안은 일정 장소만.
- UI: 카드 펼친 영역 상단 썸네일(가로 100%, 16:9, `loading="lazy"`, `alt`), 탭하면 크게 보기(선택), 출처/라이선스 문구 "이미지: Wikipedia/Wikimedia Commons". 접힌 카드에는 작은 썸네일을 둘지 판단. 데이터 절약(모바일 데이터 로밍) 고려.
- 다크모드, 360px 레이아웃, 오프라인/차단 시 동작, CSP 없음.

## 공통
- 변경 파일 범위(data.js에 `place` 필드 추가할지 vs 별도 매핑 파일 `places.js`), localStorage 키 추가.
- 완료 기준(Review 체크리스트): 한국 시각 정확성(`TripTime.now` 고정, 기기 TZ 무관), 이미지 매핑 전 행 검사, 로드 실패 처리, 회귀(65행, 금액, 알림, 자동 이동).
- **사용자 결정 필요** 표(기본안 포함).
