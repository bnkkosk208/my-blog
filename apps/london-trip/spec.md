# 런던 여행 일정관리 (london-trip) — 구현 계획 (spec)

## 1. 개요
엑셀 일정표 `런던_여행_시간대별_일정표_소호숙소버전_v7.xlsx`(2026-10-16(금) ~ 10-23(금), 시간대별 65행)를 그대로 옮긴 **일자별 일정관리 모바일 웹앱**이다.
날짜 탭으로 하루를 고르면 타임라인(시간·이동/활동·이동수단·예약 배지·예상 비용)이 나오고, 항목마다 완료 체크와 개인 메모, 사용자 일정 추가/수정/삭제를 할 수 있다(저장은 localStorage, 원본 데이터는 바꾸지 않음).
여행 당일에는 런던 시간 기준으로 지금 진행 중인 항목을 강조한다. 부가 탭에 예약 체크리스트·식당 예약방법·뮤지컬 추천·골프장 추천을 둔다. 순수 HTML/CSS/JS로 `apps/london-trip/` 안에서 자체 완결되며 블로그 메인 iframe 카드에 들어간다.

## 2. 화면 구성 (모바일 기준, 최대 폭 560px 가운데 정렬)

```
┌ 헤더 ─────────────────────────────────────┐
│ 런던 여행 일정   10/16–10/23 · 7박 8일          │
│ [런던 13:42 BST] [오늘: Day 3]                 │  ← 런던 현재시각 칩(여행 기간 중만 "오늘" 표시)
├ 상단 탭(뷰 전환) ───────────────────────────┤
│ [일정] [예약 체크] [식당] [뮤지컬] [골프]        │
├ (일정 뷰) 날짜 탭: 가로 스크롤 ───────────────┤
│ [D1 10/16 금] [D2 10/17 토] … [D8 10/23 금]     │
├ 일자 요약 카드 ─────────────────────────────┤
│ 활동 8 · 이동 6 · 완료 3/14 · 예약필요 1         │
│ 예상 교통비 £5.05~£6.60 · 입장료 £0 (식사 별도)  │
├ 타임라인 ──────────────────────────────────┤
│ 09:00–09:30 (30분) [이동] Tube  £3.30   [✓]     │
│   숙소→노팅힐 이동                               │
│ ▸ 펼치기: 비고(링크) / 식당·카페 추천 / 메모      │
│ …                                               │
│ [+ 내 일정 추가]                                 │
└────────────────────────────────────────────┘
```

### 2.1 날짜 탭
- 8개 탭: `Day N`, `10/16`, `(금)`. 순서 고정(10/16 → 10/23). 가로 스크롤 가능한 `role="tablist"`, 선택 탭은 `aria-selected="true"`.
- 초기 선택 우선순위: ① URL 해시 `#day=2026-10-18` ② **런던 기준 오늘 날짜가 여행 기간 안이면 그 날** ③ 마지막으로 본 날(`london-trip:lastDay`) ④ Day 1.
- 선택한 탭이 화면 밖이면 `scrollIntoView({inline:'center'})`. 좌우 화살표 키로 탭 이동.
- 각 탭에 작은 진행 표시(완료 수/전체, 예: `3/14`)를 표시.

### 2.2 타임라인 항목 (카드 1개 = 엑셀 1행 또는 사용자 일정 1개)
- **시간**: `시작–종료` + `(소요 N분)`. 소요는 엑셀 `E`값 그대로 표시(재계산하지 않음, 7.1 참고). 시작이 `-`이면 `– 18:20 도착`처럼 표시.
- **구분 색상**: `이동` = 주황 계열 좌측 바 + 아이콘(→), `활동` = 파랑 계열 좌측 바, `이동/활동` = 주황→파랑 그라데이션 바. (엑셀 범례: 주황=이동)
- **이동수단 칩**: `H`값. `-` 또는 빈 값이면 칩 숨김.
- **예약필요 배지**: `I`=`예약필요`면 노란 배지 `예약필요`(엑셀 범례: 노란 배경+굵게). 예약 체크리스트에서 "예약 완료"로 체크하면 배지가 `예약완료 ✓`(초록)로 바뀜.
- **예상 비용(1인)**: `M` 원문 텍스트를 그대로 표시(길면 2줄 말줄임, 펼치면 전체). `-`면 숨김.
- **완료 체크**: 카드 우측 체크박스(터치 타깃 44×44px). 완료 시 카드 흐리게 + 제목 취소선.
- **펼치기(▸/▾)**: 카드 본문 탭 또는 펼치기 버튼(`aria-expanded`). 펼친 영역:
  - 비고(주소/링크): 원문 텍스트, 링크는 클릭 가능한 `<a target="_blank" rel="noopener">`(규칙 3.4). 주소가 있으면 "지도에서 보기" 링크(Google Maps 검색 URL, 클릭 시에만 이동).
  - 주변 식당 추천(`K`) / 주변 카페 추천(`L`): ` / ` 로 분리해 목록. `★` → "인기" 작은 배지, `[웨이팅]` → "웨이팅" 배지, 괄호 안 설명은 회색 보조 텍스트. 식당예약방법 시트에 같은 이름이 있으면 "예약방법 보기" 링크(식당 탭의 해당 행으로 이동).
  - 개인 메모: `<textarea>` (입력 후 500ms 디바운스 자동 저장, "저장됨" 표시). 메모가 있으면 접힌 카드에도 📝 아이콘 대신 "메모" 텍스트 배지 표시.
- 비고·추천·메모가 모두 없는 행은 펼치기 버튼을 숨기되 메모 추가 버튼(“메모”)은 항상 제공.

### 2.3 일정관리 기능
- **완료 체크**: 원본/사용자 항목 모두 가능.
- **개인 메모**: 원본/사용자 항목 모두 가능.
- **사용자 일정 추가/수정/삭제** (포함): 타임라인 하단 `+ 내 일정 추가` → 바텀시트 폼(시작, 종료, 구분[활동/이동], 내용(필수), 이동수단, 비용 텍스트, 메모). 저장 시 시작 시간 순으로 원본과 섞여 정렬, "내 일정" 배지와 점선 테두리로 구분. 수정/삭제는 사용자 항목에만 노출(삭제는 `confirm()`).
- **원본 항목 숨기기**(선택 구현 S1): 원본은 삭제 불가. 대신 "이 항목 숨기기" 토글 → 접힌 회색 한 줄로 표시, "숨긴 항목 n개 보기"로 복원. 원본 데이터 객체는 절대 변경하지 않는다.
- 폼 검증: 내용 필수, 시간은 `HH:MM`(`<input type="time">`), 종료 < 시작이면 경고(자정 넘김으로 간주할지 묻지 않고 저장 거부).

### 2.4 현재 진행 중 항목 하이라이트
- **시간대 처리**: 모든 시각은 **런던 현지 시각(Europe/London)** 으로 해석한다. 현재 시각은 `Intl.DateTimeFormat('en-GB', { timeZone: 'Europe/London', year:'numeric', month:'2-digit', day:'2-digit', hour:'2-digit', minute:'2-digit', hourCycle:'h23' }).formatToParts(new Date())`로 런던의 날짜(YYYY-MM-DD)와 분(0~1439)을 얻어 비교한다. 사용자 기기 시간대(한국 KST 등)와 무관하게 동작.
  - 참고: 2026년 영국 서머타임(BST, UTC+1)은 10/25(일) 01:00 UTC에 종료되므로 여행 기간 전체가 BST이지만, 하드코딩하지 않고 `Intl`에 맡긴다.
  - `Intl`의 timeZone 미지원(매우 구형 브라우저) 시 하이라이트 기능만 끄고 나머지는 정상 동작.
- 판정: `오늘 === 항목 날짜 && start ≤ 현재분 < end` → "진행 중" (굵은 테두리 + `지금` 배지 + `aria-current="true"`). 동시 해당 항목이 여러 개면 모두 표시.
- 진행 중 항목이 없으면 **다음 항목**에 `다음 · n분 후` 배지.
- 오늘 탭을 처음 열 때 진행 중(없으면 다음) 항목으로 자동 스크롤(사용자가 스크롤했으면 다시 끌어오지 않음).
- 60초마다 재계산(`setInterval`), `visibilitychange`로 탭 복귀 시 즉시 재계산.
- 예외 행(엣지 케이스 7장): Day 1 첫 행(부산 출발, 시작이 KST), Day 8 행(시작 `-`)은 하이라이트 대상에서 제외(`tz` 필드로 판단).

### 2.6 일자별 요약 (계산 가능한 범위만)
- 항목 수: 활동 n · 이동 n (`이동/활동`은 "이동/활동 n"으로 별도 집계), 내 일정 n.
- 완료: `완료 수/전체`(숨긴 항목 제외, 사용자 항목 포함).
- 예약필요 n (예약완료 n).
- **예상 교통비**: 구분이 `이동` 또는 `이동/활동`인 원본 행의 `costMin` 합 ~ `costMax` 합(£, 소수 둘째 자리). 항공권(`costMin=null`)은 제외하고 "항공권 별도" 문구 추가.
- **예상 입장·이용료**: 구분이 `활동`이고 `category`가 `fee`인 행의 합(식사비·쇼핑비는 계산 불가이므로 "식사·쇼핑 별도" 문구 고정).
- 일자 시작~종료 시각(첫 행 시작, 마지막 행 종료).
- 기대값은 3.5의 표를 Review 기준으로 사용.

## 3. 데이터 설계

### 3.1 변환 방식
- 원본 엑셀은 저장소에 넣지 않는다. Build 단계에서 `docs/source-dump.txt`를 보고 **`data.js`에 손으로(또는 일회성 스크립트로) 옮긴다.** 런타임 파싱 없음.
- `data.js`는 일반 스크립트(전역 `window.TRIP_DATA` 1개, `Object.freeze`로 깊은 동결). `fetch` 없이 `file://`·GitHub Pages 어디서든 동작.
- 텍스트는 원문 그대로(오탈자·불일치 포함) 옮긴다. 추가 필드(`costMin/Max`, `links`, `category` 등)만 파생값으로 덧붙인다.
- 단, 숙소 주소는 개인정보 결정(8장)에 따라 마스킹된 값으로 넣는다(기본안).

### 3.2 스키마
```js
window.TRIP_DATA = {
  meta: {
    title: '런던 여행',
    year: 2026,
    timeZone: 'Europe/London',
    days: [ // 8개
      { date: '2026-10-16', label: '10/16(금)', dow: '금', dayNo: 1 }, … { date: '2026-10-23', label: '10/23(금)', dow: '금', dayNo: 8 }
    ],
    sourceFile: '런던_여행_시간대별_일정표_소호숙소버전_v7.xlsx'
  },
  schedule: [ /* 65개, 엑셀 행 순서 그대로 */ ],
  restaurants: [ /* 21개 */ ], restaurantNotes: [ /* 5줄 */ ],
  musicals: [ /* 8개 */ ],    musicalTips: [ /* 6줄 */ ],
  golf: [ /* 9개 */ ],        golfNotes: [ /* 6줄 */ ],
  legend: [ { color: '주황색 배경', meaning: '이동(교통) 구간' }, { color: '노란색 배경 + 굵은 글씨', meaning: '사전 예약이 필요한 항목' } ]
};
```

**schedule 항목** (엑셀 열 → 필드)
| 필드 | 타입 | 원본 | 설명 |
|---|---|---|---|
| `id` | string | 행번호 | `r02`~`r66` (엑셀 행번호, 고정 키 — localStorage가 이 값을 참조하므로 절대 바꾸지 않음) |
| `date` | string | A | `'2026-10-16'` (ISO) |
| `dateLabel` | string | A | `'10/16(금)'` 원문 |
| `dow` | string | B | `'금'` |
| `start` | string \| null | C | `'08:45'`, `-`이면 `null` |
| `end` | string \| null | D | `'17:20'` |
| `durationMin` | number \| null | E | `505`, `-`이면 `null` |
| `type` | `'이동'`\|`'활동'`\|`'이동/활동'` | F | 원문 |
| `title` | string | G | 활동/이동 내용 |
| `transport` | string \| null | H | 빈칸·`-`는 `null` |
| `reservation` | boolean | I | `I==='예약필요'` |
| `note` | string \| null | J | 비고 원문(주소 마스킹 적용) |
| `links` | `{label, url}[]` | J에서 파생 | 3.4 규칙 |
| `restaurants` | `Place[]` | K | ` / ` 분리 |
| `cafes` | `Place[]` | L | ` / ` 분리 |
| `costText` | string \| null | M | 원문, `-`는 `null` |
| `costMin` / `costMax` | number \| null | M에서 파생 | £ 숫자. 무료=0/0, 수치 없음(식사비 별도, 상품별 상이, 항공권 별도)=null |
| `costCategory` | `'transport'`\|`'fee'`\|`'free'`\|`'meal'`\|`'unknown'` | 파생 | 요약 계산용 |
| `tz` | `'Europe/London'`\|`'mixed'`\|`'Asia/Seoul'` | 파생 | r02=`'mixed'`(출발 KST·도착 런던), r66=`'Asia/Seoul'`, 나머지 런던 |

`Place = { name: string, desc: string|null, popular: boolean /* ★ */, waiting: boolean /* [웨이팅] */, raw: string }`
- 예: `Dishoom Permit Room Portobello[웨이팅](인도, 브런치)` → `{ name:'Dishoom Permit Room Portobello', desc:'인도, 브런치', popular:false, waiting:true }`.
- 괄호가 없으면 `desc:null` (예: `Muffin Break Notting Hill`, `Fishoria Covent Garden`).

**restaurants 항목**: `{ id:'rs02'…, date:'2026-10-16', dateLabel, meal:'저녁'|'점심', name, cuisine, reservation:'예약 필수'|'예약 권장'|'예약 불가 (워크인/웨이팅)', method, siteText, links, note }` (원문 G열은 `siteText`, 링크로 만들 수 있으면 `links`).
**musicals 항목**: `{ id:'mu02'…, title, genre, theatre, area, runtime, booking, siteText, links, note, inSchedule:boolean /* 맘마미아·라이온킹 */ }`

### 3.4 링크 텍스트 → URL 규칙

## 5. localStorage 키 설계
접두사 `london-trip:` (같은 오리진의 블로그·2048과 충돌 방지). 모든 접근은 try/catch, 실패 시 메모리 상태로만 동작하고 상단에 "이 브라우저에서는 저장되지 않습니다" 안내 1회.

| 키 | 값(JSON) | 설명 |
|---|---|---|
| `london-trip:v1:done` | `{ [itemId]: true }` | 완료 체크. itemId는 원본 `r02`… 또는 사용자 `u_<timestamp36>` |
| `london-trip:v1:memo` | `{ [itemId]: string }` | 개인 메모(최대 2000자, 빈 문자열이면 키 삭제) |
| `london-trip:v1:custom` | `CustomItem[]` | 사용자 일정 `{ id, date, start, end, type, title, transport, costText, createdAt, updatedAt }` |
| `london-trip:v1:hidden` | `{ [rowId]: true }` | 숨긴 원본 행(S1) |
| `london-trip:v1:booked` | `{ [rowId]: true }` | 예약 체크리스트 "예약 완료" |
| `london-trip:lastDay` | `'2026-10-18'` | 마지막으로 본 날짜(버전 무관) |
| `london-trip:lastView` | `'schedule'`… | 마지막 뷰 탭 |

- 읽을 때 스키마 검증: 객체/배열 형태가 아니거나, 원본에 없는 `r..` id, 잘못된 날짜·시간 형식 항목은 버리고 나머지만 사용(전체를 날리지 않음).
- 버전 `v1` 구조가 바뀌면 `v2` 키로 이전 후 `v1` 삭제.
- 테마는 블로그의 `localStorage['theme']`(`light`/`dark`)을 **읽기만** 한다(쓰지 않음).

**초기화(리셋)**
- 일정 뷰 하단(또는 헤더 ⋯ 메뉴) "설정" 영역:
  - `이 날 체크 초기화` — 선택한 날의 done만 삭제.
  - `전체 초기화` — `london-trip:` 접두사 키를 모두 삭제(`confirm()` 2단계: "완료·메모·내 일정이 모두 삭제됩니다"). 원본 데이터는 영향 없음.
  - (선택 S2) `내보내기` — 사용자 상태를 JSON 파일로 다운로드(`Blob` + `a[download]`), `가져오기` — 파일 선택 후 검증·병합. 기기 변경 대비.

- **색상 토큰** (`:root`, 블로그 톤과 맞춤):
  - `--bg #ffffff` / `--bg-subtle #f4f6fa` / `--text #1b1f27` / `--text-muted #5b6475` / `--border #dfe3ea`
  - `--accent #2458d6`(블로그와 동일, 선택 탭·버튼·활동 바)
  - `--move #e8780c`(이동 바·칩, 엑셀 "주황=이동") / `--move-bg #fff3e6`
  - `--reserve #f2c200`(예약필요 배지 배경, 글자 `#3d3000`, 엑셀 "노랑=예약") / `--booked #1f9d55`
  - `--now #d6336c`(진행 중 테두리·`지금` 배지)
  - `--danger #c92a2a`(삭제, 예약 필수)
- **다크모드**: `@media (prefers-color-scheme: dark)` + `:root:not([data-theme="light"])`, 그리고 `:root[data-theme="dark"]`에 같은 값 재정의(블로그와 같은 방식). 다크값 예: `--bg #16181c`, `--bg-subtle #1f232a`, `--text #e6e9ef`, `--text-muted #9aa3b2`, `--border #2e3440`, `--accent #7aa2ff`, `--move #ff9f43`, `--move-bg #3a2a17`, `--reserve #e0b400`, `--now #ff6b9a`. 모든 글자/배경 쌍 대비 4.5:1 이상(배지 작은 글씨 포함).
- **폰트**: 블로그와 같은 시스템 한글 스택 `-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Pretendard", "Malgun Gothic", "Noto Sans KR", sans-serif`. 시간 표시는 `font-variant-numeric: tabular-nums`. 본문 16px(iOS 입력 확대 방지), 보조 13~14px.
- **터치 타깃**: 체크박스·탭·버튼 최소 44×44px, 인접 타깃 간격 8px 이상. 날짜 탭 높이 56px.
- **레이아웃**: 좌우 16px 여백, 최대 폭 560px. 360px 폭에서 가로 스크롤 없음(긴 URL·영문 식당명 `overflow-wrap: anywhere`). 뷰 탭·날짜 탭은 스크롤 시 상단 고정(`position: sticky`).
- **모션**: 펼치기/바텀시트 150~200ms, `prefers-reduced-motion: reduce`면 끔.
- **접근성**: 체크박스는 실제 `<input type="checkbox">` + `<label>`(항목 제목 포함), 탭은 WAI-ARIA tabs 패턴, 펼치기는 `<button aria-expanded aria-controls>`, 바텀시트는 `<dialog>`(Esc로 닫힘, 열릴 때 첫 입력에 포커스), 진행 중 항목 변경은 `aria-live="polite"`로 1회 안내.
- **iframe 대응**: `overscroll-behavior: contain`, 높이 640px iframe에서 헤더+날짜 탭+요약+첫 카드 2~3개가 보이도록 헤더를 컴팩트하게. iframe 안에서는 우상단에 "새 창에서 열기 ↗"(`window.self !== window.top`일 때만).

## 7. 엣지 케이스
1. **r66 (10/23) 시작 `-`, 소요 `-`**: `start=null`, `durationMin=null`. 시간 영역은 `– 18:20 도착 (한국 시각)` 표시. 정렬 시 맨 앞에 두되 그날 유일한 행. 하이라이트 대상 제외. 사용자 일정을 10/23에 추가하면 `start=null` 행은 항상 첫 번째.
2. **r02 시간대 혼재**: 08:45는 부산(KST) 출발, 17:20은 히드로(런던) 도착이며 `E=505`는 시계 숫자 차이일 뿐 실제 비행시간과 다르다. 화면에 `08:45 (한국) – 17:20 (런던)` 보조 표기, 소요는 원문 505분 그대로 + "(시차 미반영)" 툴팁. 하이라이트 제외.
3. **자정 근처**: 원본에 자정을 넘는 행은 없다(가장 늦은 종료 r21 23:00). 그래도 `end < start`인 사용자 항목은 저장 거부(2.3). 런던 시각 23:59→00:00이 되면 1분 타이머가 "오늘"을 다음 날로 바꾸되, 사용자가 다른 날 탭을 보고 있으면 탭을 강제로 옮기지 않고 헤더의 "오늘: Day N" 칩만 갱신.
4. **여행 기간 밖 접속**:
   - 여행 전(런던 날짜 < 2026-10-16): Day 1 선택, 헤더에 `D-n` 표시(예: 10/14 접속 시 `D-2`), 하이라이트 없음.
   - 여행 후(> 2026-10-23): 마지막으로 본 날 또는 Day 1, 헤더에 "여행 종료" 표시, 하이라이트 없음.
   - 연도가 다른 경우(2027년 등)도 날짜 비교는 ISO 문자열 전체로 하므로 "여행 종료"로 처리.
5. **겹치거나 비는 시간**: 원본에 공백 구간이 있다(예: 10/20 08:15~09:00, 10/16 이전 등). 공백은 별도 표시하지 않음(선택: 30분 이상 공백은 얇은 점선 "빈 시간 45분"). 겹치는 사용자 일정은 시작 시간 순, 같으면 원본 먼저.
6. **`이동/활동`(r57)**: 교통비 계산에 포함(costCategory=transport), 색상은 그라데이션 바, 요약에는 별도 카운트.
7. **빈 값 표기**: `H='-'`, `M='-'`, 빈 셀 → 모두 `null`로 정규화하고 UI에서 숨김.
8. **localStorage 차단/손상**: 5장 규칙. 손상된 JSON(`"abc"`)이 있어도 앱이 깨지지 않음.
9. **긴 텍스트**: r29 비고, r43 비용, K열 6개 식당 목록 등 — 접힌 상태 2줄 말줄임, 펼치면 전부.
10. **URL 해시 잘못된 값**(`#day=2026-12-01`): 무시하고 기본 규칙으로 선택.
11. **JS 비활성**: `<noscript>`로 "JavaScript가 필요합니다" 안내.

### 13.1 확정 방식과 방식별 제약 (사용자 확정, 2026-10-14)
**브라우저 알림(Notification API) + 앱 내 토스트 + 캘린더 내보내기(.ics, VALARM)** 조합. 서버 푸시는 범위 밖.
- 앱이 열려 있을 때: 시스템 알림(권한 허용 시) + 항상 앱 내 토스트(권한 거부·미지원·iframe이면 토스트만).
- 앱이 닫혀 있을 때: 미리 .ics를 휴대폰 캘린더에 넣어 두면 OS가 알린다(닫힌 상태에서 확실한 유일한 방법).

| 방식 | Android Chrome | iOS Safari | 데스크톱 브라우저 | 블로그 iframe 안 |
|---|---|---|---|---|
| 앱 내 토스트(+진동·소리) | 화면에 떠 있을 때만. `vibrate` 지원 | 화면에 떠 있을 때만. `vibrate` 미지원 | 탭이 열려 있으면 동작(백그라운드 탭은 타이머가 최대 1분 단위로 지연) | 동작 |
| Notification API | `new Notification()` 불가(Illegal constructor). **Service Worker의 `showNotification`만 가능**(A4). 브라우저가 백그라운드에서 멈추면 안 울림 | 일반 탭은 미지원. 홈 화면에 추가한 웹앱(16.4+, manifest 필요)에서만 → 이번 범위에서는 토스트만 | `new Notification()` 동작. 권한은 사용자 클릭 때만 요청 | 권한 요청이 막히거나 제한됨 → 요청하지 않고 "새 창에서 열면 시스템 알림 사용 가능" 안내 |

| (참고) SW + Push / Notification Triggers | Push는 푸시 서버·VAPID 키가 필요해 정적 사이트로 불가. Notification Triggers(`showTrigger`)는 Chrome 실험이 중단되어 표준이 아님 → 범위 밖 | | | |

### 13.2 알림 설정 UI
- **카드 벨 버튼**: 각 카드 우측(체크박스 옆) `<button aria-pressed>` 44×44px, 라벨 `"알림 켜기: {제목}"`. 켜지면 채운 벨 + 시간 옆에 `🔔 30분 전` 텍스트 배지(색 외 구분). 시작시간이 없는 행(r66, 시작 없는 사용자 일정)은 벨 `disabled`(title "시작 시간이 없어 알림 불가").
- **항목별 시점**: 펼친 영역에 `알림 시점` `<select>`(5/10/15/30/60/90/120분 전, 기본 = 전역 기본값). 바꾸면 그 항목을 다시 예약.
- **알림 패널**: 일정 뷰 일자 요약 카드 바로 아래 `<details class="alarm-panel">`(기본 접힘). summary 줄에 `🔔 다음 알림 10/18 16:00 · 런던아이 탑승 (30분 전)` 또는 `알림 꺼짐`. 펼치면:
  1. 전역 `알림 사용` 스위치 — 끄면 아무것도 울리지 않음(항목 설정은 유지, 벨은 흐리게).
  2. 시스템 알림 상태: `허용됨` / `거부됨(브라우저 설정에서 변경)` / `미지원(앱 안 알림만)` / `iframe 안: 새 창에서 열기 ↗` / `[시스템 알림 허용]` 버튼(클릭 때만 `requestPermission`).
  3. 기본 알림 시점 select, `소리` 체크(기본 끔), `진동` 체크(지원 기기만 표시).
  4. 일괄 버튼: `예약필요 항목 켜기`, `이동 항목 켜기`(이동/활동 r57 포함), `이 날 모두 켜기`, `모두 끄기`(confirm). 결과를 기존 aria-live로 "알림 7개를 켰습니다" 안내.
  5. `다가오는 알림`: 지금 이후 최대 5개(날짜·알림 시각·제목·N분 전). 누르면 그 날 탭으로 이동해 카드 펼침. 15분 이내 놓친 알림은 `놓침` 배지로 맨 위.
  6. `캘린더로 내보내기(.ics)`: 범위 라디오 `알림 켠 항목(전 일정)`(기본) / `이 날 전체` / `여행 전체`, `내 일정 포함`(기본 켬), `[.ics 받기]`. 아래 기기별 1줄 안내(iOS·Android·PC).
- **토스트**: 화면 하단 고정(`env(safe-area-inset-bottom)`, 최대 폭 560px). `16:00 런던아이 탑승 · 30분 후 시작` + `[보기]`(카드로 스크롤·펼침) + `[닫기]`(각 44px). 같은 시각 여러 개는 한 토스트에 최대 3개 + "외 n개". 자동으로 닫지 않음. 새 `aria-live="assertive"` 영역으로 낭독, 포커스는 옮기지 않음.

### 13.3 저장소 (5장 보완)
| 키 | 값(JSON) | 설명 |
|---|---|---|
| `london-trip:v1:alarm` | `{ enabled, lead, sound, vibrate, items: { [itemId]: { lead } } }` | 전역 설정 + 켠 항목(`items`에 있으면 켜짐). 기본 `{enabled:true, lead:30, sound:false, vibrate:true, items:{}}` |
| `london-trip:v1:alarmFired` | `{ [itemId]: firedKey }` | 이미 울린 알림. `firedKey` = 알림 시각 epoch ms 문자열. 시점·시작시간이 바뀌면 키가 달라져 다시 예약됨 |
- 검증: 형식이 틀리면 기본값. `lead`는 허용 목록(5/10/15/30/60/90/120)만, 아니면 전역값. itemId는 기존 `validItemId`만 통과, 존재하지 않는 사용자 id는 로드 시 제거. `alarmFired` 값은 숫자 문자열만.
- 사용자 일정 삭제 시 `items`·`alarmFired`에서 그 id도 지움. 숨긴 원본(S1)은 설정은 남기되 울리지 않음.
- **백업(S2)**: `exportData`에 `alarm` 필드 추가(`version` 1 유지, `alarm` 없는 옛 파일도 가져오기 가능). `importData`는 `alarm.items`만 병합(전역 설정은 덮어쓰지 않음). `alarmFired`는 내보내지 않음.
- 전체 초기화(접두사 삭제)에 두 키도 포함. "이 날 체크 초기화"는 알림에 영향 없음.

### 13.4 스케줄링 로직
- **기준 시각**: `time.js`에 순수 함수 `TripTime.toEpoch(dateISO, 'HH:MM', tz)` 추가 — Intl로 해당 시각의 오프셋을 구해 UTC ms로 변환. Intl 미지원 시 고정값(런던 BST UTC+1 — 2026년 서머타임 종료가 10/25라 여행 전체가 BST, 서울 UTC+9). 알림 시각 = `toEpoch(시작) − lead×60000`, 현재 = `TripTime.now().getTime()`(테스트용 덮어쓰기 그대로 반영). 기기 시간대와 무관.
- **시간대 혼재**: r02 시작 08:45는 `Asia/Seoul`로 변환(= 10/15 23:45 UTC). r66은 시작이 없어 대상 아님. 나머지 원본·사용자 일정은 `Europe/London`.
- **대상**: 전역 `enabled` && `items`에 있음 && 시작시간 있음 && 숨김 아님 && 완료 체크 안 됨(A8).
- **타이머**: 기존 1분 `setInterval`과 `visibilitychange`에서 `TripAlarm.check()`를 함께 호출(재사용). 추가로 다음 알림까지 `setTimeout` 1개(24시간 넘으면 걸지 않음)로 열려 있을 때 정시에 울림. 설정·데이터 변경 시 다시 계산.
- **check() 규칙**: `알림시각 ≤ 지금 < 알림시각 + 15분` && `alarmFired[id] !== firedKey`이면 발사 후 기록. `지금 ≥ 알림시각 + 15분`이면 울리지 않고 기록만(오래된 알림을 한꺼번에 띄우지 않음). 처음 켠 시점에 이미 지난 일정은 울리지 않고 "이미 지난 일정" 안내.
- **중복 방지**: 발사 직전 localStorage의 `alarmFired`를 다시 읽어 확인·기록 후 표시(여러 탭 대비). 시스템 알림 `tag: 'lt-' + id + '-' + firedKey`로 OS 단에서도 합쳐짐.
- **발사**: ① 토스트(항상) ② 권한 `granted`이고 top 창이면 시스템 알림 — SW 등록돼 있으면 `registration.showNotification`, 아니면 `new Notification`(try/catch, 실패 시 토스트만) ③ 진동 설정+지원 시 `navigator.vibrate([200,100,200])` ④ 소리 설정 && `AudioContext`가 사용자 제스처(설정 클릭)로 resume된 경우만 0.3초 비프. 시스템 알림 클릭 → 창 focus + 카드 이동.
- 놓친 알림 문구: `16:00 런던아이 탑승 · 알림 시각 3분 지남`(이미 시작했으면 `시작됨`).

### 13.5 캘린더 내보내기(.ics)
- RFC 5545: `VERSION:2.0`, `PRODID:-//london-trip//KO`, `CALSCALE:GREGORIAN`, `METHOD:PUBLISH`, `X-WR-CALNAME:런던 여행`. CRLF, 75옥텟 접기(UTF-8 글자 중간에서 자르지 않음), TEXT의 `\ ; , 개행` 이스케이프.
- 시간은 **UTC(`…Z`)로 변환**해 VTIMEZONE 없이 기록(`toEpoch` 재사용). r02: DTSTART 08:45 KST → `20261015T234500Z`, DTEND 17:20 런던 → `20261016T162000Z`로 실제 시각이 맞게 들어감.
- VEVENT: `UID:{id}@london-trip`(다시 내보내도 같은 UID라 캘린더가 갱신), `DTSTAMP`, `DTSTART`, `DTEND`(종료 없으면 시작+15분), `SUMMARY`(이동이면 `→ ` 접두), `LOCATION`(addresses[0]), `DESCRIPTION`(이동수단·예상비용·비고 원문, **메모는 제외**). 알림 켠 항목만 `BEGIN:VALARM / ACTION:DISPLAY / TRIGGER:-PT{lead}M / DESCRIPTION:{제목}`.
- 제외: 시작시간 없는 행(r66 등), 숨긴 원본, (`내 일정 포함` 끔이면) 사용자 일정. 대상 0개면 "내보낼 일정이 없습니다".
- 파일: `Blob(…, {type:'text/calendar;charset=utf-8'})` + `a[download]`(S2와 같은 방식). 이름 `london-trip-alarms.ics` / `london-trip-2026-10-18.ics` / `london-trip-all.ics`.

### 13.7 엣지 케이스
1. 기기 잠김·브라우저 종료·백그라운드 정지 → 앱 알림은 안 울림. 패널에 "앱이 닫혀 있으면 울리지 않습니다. 캘린더 내보내기를 함께 쓰세요" 고정 안내.
2. 사용자 일정 시간 수정 → firedKey가 바뀌어 다시 예약. 시작시간을 지우면 알림 해제, 삭제하면 설정 제거.
3. 같은 시각 여러 알림 → 토스트 1개로 묶음, 시스템 알림은 항목별.
4. 여행 전 한국에서 사용 → epoch 비교라 그대로 동작(r02 30분 전 = 한국 08:15).
5. 권한 `denied`·미지원·iframe → 토스트만 + 패널에 이유 표시. 권한 요청 버튼을 반복해서 띄우지 않음.
6. localStorage 차단 → 메모리로만 동작(기존 "저장되지 않습니다" 안내 재사용).
7. 손상된 alarm 값(`"abc"`, `lead:7`, `r99`) → 유효한 부분만 사용.
8. 데스크톱 백그라운드 탭 → 최대 약 1분 늦게 울릴 수 있음(허용).

## 14. 현재 위치 자동 이동 (v3)
사용자 요구: "일자, 시간 체크해서 항상 그 위치로 이동해 있게". 앱은 **런던 기준 오늘 탭 + 진행 중(없으면 다음) 카드**에 항상 맞춰져 있어야 한다. 이 장은 **2.1 초기 선택 ②③, 2.4 "처음 열 때 1회 자동 스크롤", 7장 3번(자정 넘김 시 탭 유지)을 대체**한다.

### 14.1 "현재 위치" 정의 (`currentTarget()` → `{day, itemId|null}`)
- 여행 중: 런던 오늘 탭 + 진행 중 항목(여러 개면 첫 번째), 없으면 다음 항목, 그날 남은 항목이 없으면 그날 마지막 항목.
- 여행 전: Day 1 + r02(첫 일정). 하이라이트 없음은 7장 4번 유지.
- 여행 후: Day 8(마지막 날) 맨 위. (lastDay 기억은 사용하지 않음)
- 숨긴 항목·하이라이트 제외 항목(r66 등)은 대상에서 건너뛴다. `Intl` 미지원 시 자동 이동 기능 전체 끔.

### 14.2 이동 시점 (`syncToNow(reason)`)
1. 첫 로드 (해시 없을 때)
2. 탭/앱 복귀: `visibilitychange`(visible), `pageshow`(bfcache 복귀)
3. 1분 타이머에서 **대상 키(`day|itemId`)가 바뀔 때** (진행 중 항목 전환, 다음 항목 전환)
4. 런던 자정 넘김(오늘 날짜 변경) — 탭도 새 날짜로 이동
- 대상 키가 그대로이고 이미 그 위치면 스크롤하지 않는다(타이머마다 덜컹거림 방지).

### 14.3 사용자 조작과 충돌 방지
- 조작 감지: 날짜 탭 클릭, 뷰 탭 클릭, wheel/touchmove/스크롤 키, 카드 펼치기·접기·체크, 검색/필터. 감지 시 `state.lastInteract = now`.
- **보류**: 마지막 조작 후 `HOLD_MIN`(기본 3분) 동안 자동 이동하지 않는다. 보류가 끝난 다음 이동 시점(타이머·복귀)에 현재 위치로 복귀.
- **절대 이동 금지**: 입력 요소(input/textarea/select/contenteditable) 포커스 중, 열린 `dialog`/바텀시트/알림 패널, 텍스트 선택 중. 해제 후 다음 시점에 판단.
- 탭/앱 복귀(14.2-2)는 보류 시간과 무관하게 이동한다(단 위 "절대 금지" 조건은 지킴). 기존 `state.autoScrolled`·`state.userScrolled`는 제거하고 이 규칙으로 통합.

### 14.4 "지금으로" 버튼
- 현재 위치에서 벗어났을 때(다른 날짜/뷰, 또는 대상 카드가 뷰포트 밖) 우하단 고정 원형/알약 버튼 `지금으로` 표시(44px 이상, 하단 safe-area 보정, 토스트와 겹치지 않게 위로).
- 클릭 시 보류 해제 + 즉시 `syncToNow('button')` + 카드 flash. 현재 위치에 있으면 숨김. 여행 후에는 표시하지 않음.
- `aria-label="현재 일정으로 이동"`, 키보드 접근 가능.

### 14.5 뷰 탭 (예약/식당/뮤지컬/골프 등)
- 보류 시간 동안은 그대로 둔다. 보류가 끝나면 **일정 뷰로 자동 전환**하지 않고 "지금으로" 버튼만 표시(기본안, 14.8 B3).
- 탭/앱 복귀 시에는 일정 뷰로 전환해 이동(기본안). `lastView` 복원은 여행 중에는 무시, 여행 전·후에는 유지.

### 14.6 해시와의 우선순위
- `#day=…&item=…`(알림 클릭) 또는 `#day=…`로 진입/`hashchange` 시: 해당 위치로 이동하고 이를 **사용자 조작으로 간주**(보류 시작). 보류 후에는 현재 위치로 복귀.
- 자동 이동 시 해시는 바꾸지 않는다(`history.replaceState`로 해시 제거만 — 새로고침 시 고정되지 않게).

### 14.7 스크롤 계산
- 기존 `scrollPageTo(node, stickyHeight())`(window.scrollTo) 유지 — iframe에서 부모 스크롤 금지, `scrollIntoView` 사용 금지(날짜 탭 가로 중앙 정렬 제외).
- `behavior`: 기본 `smooth`, `prefers-reduced-motion: reduce`면 `auto`. 렌더 직후 `requestAnimationFrame` 1회 뒤 계산.
- 자동 스크롤이 일으킨 scroll 이벤트는 조작으로 세지 않는다(wheel/touch/key만 감지하므로 자연 충족).

### 14.8 파일 범위 · 저장소

## 15. 한국 시간 표시 + 장소 이미지 (v4)
사용자 요구: "한국 시간도 추가해주고, 장소별로 이미지 참고 자료도 추가로 표시해줘." 이 장은 **1장·8장의 '외부 요청 없음' 원칙에 장소 이미지 예외를 추가**하고, 2장 헤더·카드 구성에 아래 요소를 더한다. 나머지는 1~14장 유지.

### 15.1 한국 시간
- **헤더 시계**: `런던 15:59 BST · 한국 23:59 (+8h)`. 한국 시각은 `TripTime.format(TripTime.now().getTime(), 'Asia/Seoul')`. 시차는 두 `format` 결과(날짜+분)의 차로 계산(하드코딩 금지 — 10/25 GMT 전환 후 +9h 자동). 1분 타이머로 함께 갱신. 360px에서 넘치면 한국 시각을 둘째 줄로.
- **일정 카드**: 런던 `시작–종료` 아래 보조 줄 `🇰🇷 23:30–01:20 +1일`(작은 회색 글씨). `toEpoch(date, hhmm, 'Europe/London')` → `format(ms, 'Asia/Seoul')`, 한국 날짜가 행 날짜와 다르면 `+1일`(음수면 `-1일`). 종료 없음/시간 없음 행은 표시 생략.
- **tz가 다른 행**: `tz:"mixed"`(r02)는 시작=한국(부산 출발), 종료=런던(히드로 도착)으로 해석 — 보조 줄 `한국 08:45 출발 · 도착 시 한국 01:20 +1일`. `tz:"Asia/Seoul"`(r66)은 원래 시각이 한국이므로 보조 줄을 `런던 10:20`(역변환)으로 표시. 해석은 Build에서 note·원본으로 확인.
- **사용자 일정(custom)**: 런던 기준으로 동일 처리.
- **영향 범위**: 다가오는 알림 목록(app.js `A.upcoming`)에 `(한국 23:30)` 괄호 보조 표기 추가. 토스트·시스템 알림 본문은 변경 없음(짧게 유지). `.ics`는 UTC라 불변. 자동 이동(14장)·상태 계산은 런던 기준 그대로.
- **토글**: 설정 영역 `한국 시간 표시` 스위치(기본 켬, 헤더는 항상 표시·카드 보조 줄만 on/off) — 사용자 결정 C1.

- 위치: **카드 펼친 영역 상단**, 가로 100%·`aspect-ratio:16/9`·`object-fit:cover`·`border-radius`, `<img loading="lazy" decoding="async" alt="{장소 한글명} 사진">`. 아래 캡션 `이미지: Wikipedia/Wikimedia Commons · 문서 보기 ↗`(`content_urls.mobile.page`, `rel="noopener noreferrer"`, 새 탭).

## 16. 사진 기본 펼침 + 일자 스와이프 (v5)
사용자 요구: "사진은 기본값으로 펼치기로 해주고, 일정 페이지에서 일자별로는 좌우 스와이핑 기능을 넣어줘." 이 장은 **15.4의 '사진은 펼친 영역 상단'·'접힌 카드에는 🖼 표시만'(C3)을 대체**한다. 나머지는 1~15장 유지.

### 16.1 사진 기본 표시
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| ① 접힌 카드에도 사진 항상 표시 | 사진은 카드 헤더(시간·제목) 아래 16:9로 상시 노출, 비고·추천·메모는 기존처럼 펼치기 | 펼침 상태 관리 불변, 목록이 일관 | 카드 높이 증가 |
| ② 사진 있는 카드를 기본 펼침 | 사진 카드만 처음부터 펼친 상태 | 구현 단순 | 비고·메모까지 펼쳐져 목록이 매우 길어짐, 펼침 상태 저장 규칙과 충돌 |
- **기본안 ①**. 사진·캡션(출처·라이선스)은 접힘과 무관하게 표시, 펼친 영역에서는 중복 표시하지 않음. 🖼 표시는 제거.
- `<img loading="lazy" decoding="async" width height>`: places.js의 실제 픽셀 크기를 width/height로 넣고 CSS `aspect-ratio:16/9; object-fit:cover; width:100%; height:auto` — 로드 전후 레이아웃 변화 0(14장 자동 이동 스크롤 위치가 밀리지 않게).
- 설정 `장소 이미지 표시` 토글 유지: 끄면 사진 영역 미렌더(검색 링크도 숨김). 사진 탭 → 기존 크게 보기 dialog.
- 완료(체크) 항목: 카드 흐림 처리에 사진도 포함(opacity 동일), 숨긴 항목은 렌더 안 함.

### 16.2 일자 좌우 스와이프
- 대상: 일정 뷰의 타임라인 영역(`#panel-schedule` 카드 목록). 왼쪽 스와이프 → 다음 날, 오른쪽 → 이전 날. Day 1/Day 8 경계에서는 이동 없음(가장자리 저항 피드백만). 키보드 화살표의 순환 규칙과 달리 **스와이프는 순환하지 않음**.
- 판정(Pointer Events, `pointerType==='touch'`만 — 기본안): `pointerdown`에서 시작점 기록 → 이동량 10px 넘을 때 방향 결정: `|dx| > |dy| * 1.5`면 수평 제스처로 잠금, 아니면 세로 스크롤로 보고 이번 제스처 무시. 확정 조건: `|dx| ≥ 60px` **또는** (`|dx| ≥ 30px` 그리고 속도 ≥ 0.5px/ms). 제스처 시간 제한은 두지 않음.
- 무시 조건: 두 번째 포인터(멀티터치) 등장 시 취소, 시작 요소가 `input/textarea/select/[contenteditable]/dialog/바텀시트/알림 패널/날짜 탭 줄(자체 가로 스크롤)` 안이면 무시, 텍스트 선택 존재 시 무시, `pointercancel` 시 원위치. 10px 미만 이동은 일반 탭으로 처리(카드 펼치기 클릭 유지). 스와이프 성공 직후 발생하는 click은 1회 억제.
- CSS: 타임라인 영역에 `touch-action: pan-y`(세로 스크롤·핀치는 브라우저에 맡김). 리스너는 passive, `preventDefault` 사용 안 함.
- 피드백: 수평 잠금 후 타임라인을 `translateX(dx*0.4)`로 살짝 따라오게, 경계에서는 `dx*0.15`. 확정 시 180ms 슬라이드 아웃 → 날짜 변경 렌더 → 반대편에서 슬라이드 인. 미확정 시 원위치 복귀. `prefers-reduced-motion: reduce`면 따라오기·애니메이션 없이 즉시 전환.
- 전환 후: 기존 날짜 탭 선택 함수 재사용(aria-selected·탭 줄 가로 중앙 정렬 동기화), 페이지는 타임라인 맨 위(sticky 아래)로 `scrollPageTo` — 단 이미 그 위치 아래면 이동, 위면 그대로. 해시 변경 없음.
- 14장 연동: 스와이프 시작(수평 잠금) 시 `markInteract()` → 3분 보류. 기존 `touchmove` 감지와 중복돼도 무해.
- iframe·iOS: 화면 왼쪽/오른쪽 가장자리 20px 안에서 시작한 제스처는 무시(iOS 뒤로가기 제스처와 충돌 방지). 수평 제스처는 부모 페이지 세로 스크롤을 막지 않음(`pan-y`).
- 데스크톱 마우스 드래그: 지원 안 함(기본안). 키보드는 기존 탭 화살표 규칙 유지.
- 안내: 첫 일정 뷰 진입 시 1회 토스트 `← 좌우로 밀어 날짜 이동 →`(터치 기기 `matchMedia('(pointer:coarse)')`일 때만), 표시 후 localStorage 기록.
